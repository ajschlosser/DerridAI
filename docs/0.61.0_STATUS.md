# 0.61.0 — Undulating Umbrellabird: final status

> Historical release-status record. “Deferred” items below describe the state at 0.61.0; several were completed in later releases. Do not use this file as a current backlog.

All planned work is complete; version identifiers read 0.61.0. This file records what was actually verified.

## Completed

- Approved-profile RAG model fix; separate Ruff, mypy, and ESLint CI jobs with tracked debt (`STATIC_ANALYSIS_FOLLOWUPS.md`).
- Backend decomposition (`corpus_metadata.py`, `corpus_pipeline.py`, `corpus_publication.py`, staged enrichment and build orchestration) and frontend lifecycle/review domain extraction. The completed implementation plan was later removed as redundant historical scaffolding.
- Silent-exception audit across `api/app` (`tests/test_failure_visibility.py`); remaining swallows are commented as safe.
- Authentication: environment-driven `SESSION_COOKIE_SECURE`; SQLite-backed per-username failed-login throttle; HTTP 429 with `Retry-After` and a localized wait message for locked usernames (identical for unknown usernames).
- **Metadata population fix:** discourse/quotation/indexing response schemas now require `metadata` and its fields, so schema-constrained decoding can no longer return assessments without values. Confident-but-empty attribution fields stay unresolved (`no_value_returned`). Tests: `tests/test_confident_autofill.py`.
- UI: Search/Research in-place empty states, operations panel/pill fixes, sidebar highlight and scroll, `Ctrl K` hint, corpus-build progress labels, translated breadcrumbs, and small bug fixes (raw `{placeholders}`, stale sign-in version, duplicated dialog text).
- Documentation: `CHANGELOG.md`, `CONTRIBUTING.md`, `docs/ARCHITECTURE.md`, `docs/notes/0.61.0.md`, and User Guide sections for sign-in protection, empty states, and metadata population.

- `pytest -q`: 155 passed. `ruff check api/app`, `mypy`, `compileall`: clean.
- `npm run lint`, `typecheck`, `test:unit` (45), `build`, `build-storybook`: pass.
- Playwright + axe: 42 passed. Port 6006 was occupied by an unrelated Storybook, so a local uncommitted config on port 16006 with one worker and CI's single retry was used.
- The metadata fix was exercised through the real `_enrich_record` path against local Ollama: `gemma4:e2b` populated all discourse fields; `qwen3.5:2b` populated most, and left speaker/position holder/target empty, which now surface as unresolved.
- Docker images for `web` and `api` were built from this branch and run as a separate compose project on other ports with a scratch data directory (since removed). Verified there: session cookie has no `Secure` flag by default, lockout behavior for real and unknown usernames, fr-CA empty states, French breadcrumbs, and the localized lockout message.
- Node 26 breaks Vitest/happy-dom (`localStorage.clear`); CI's Node 22 is the supported runtime.

## Deferred / judgment calls

- No per-IP throttle: behind the nginx proxy every client shares one source address unless forwarding headers are trusted, and the lock is per username, so someone who knows a username can lock that account for the lockout period.
- Records enriched before the metadata fix are not repaired automatically; use "Run metadata enrichment again" for Discourse / attribution ("Retry metadata" skips completed families).
- "Retry metadata" still does not re-run completed families or cover confident-but-empty fields; changing that is a separate design decision.
- Broader `main.py` route and Chroma-store splits and SA-01–SA-16 remain follow-ups. The earlier ChatGPT decomposition commits were verified by tests but not reviewed line by line.
- `AGENTS.md` copyright lines (1 and 45) still say "Aaron John Schlosser, PhD" to match every source-file header; only the commit-identity line was changed as requested.
- Some breadcrumb parts still use English fragments (for example "page N" for PDFs).
