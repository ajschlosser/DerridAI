# Testing and Quality-Gate Requirements

**Scope:** Backend/frontend test taxonomy, contract tests, E2E/workflow tests, accessibility, localization, builds, formatting/lint/type checks, release consistency, and test-to-requirement traceability.  
**Parent requirements:** [Global requirements](GLOBAL_REQUIREMENTS.md)

## Test architecture requirements

| ID             | Requirement                                                                                                                                                    | Acceptance criteria                                                                                                                                                | Parent               | Implementation trace                        | Verification                                            |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------- | ------------------------------------------- | ------------------------------------------------------- |
| **PRD-QA-001** | The repository MUST maintain explicit test categories appropriate to the boundary being verified rather than treating all tests as interchangeable unit tests. | Unit, regression, contract, integration, characterization, workflow, accessibility, and slow tests use the documented taxonomy/markers/commands.                   | PRD-G-036            | [Backend test suite](../../tests/README.md) | **Direct:** pytest marker configuration and CI commands |
| **PRD-QA-002** | Tests SHOULD validate product behavior/invariants rather than incidental source text or private implementation shape.                                          | New tests primarily exercise public/domain behavior; source-text assertions are limited to deliberate static/contract gates and documented characterization cases. | PRD-G-035, PRD-G-036 | [Backend test suite](../../tests/README.md) | **Process/architectural:** test review                  |
| **PRD-QA-003** | Test files SHOULD document what area they cover, why the behavior matters, and how the test establishes it.                                                    | New backend test modules/functions follow the repository's documented explanatory-docstring convention.                                                            | PRD-G-036, PRD-G-037 | [Backend test suite](../../tests/README.md) | **Process:** code review/static conventions             |
| **PRD-QA-004** | Tests MUST NOT depend on live Ollama, GPU, Docker, or production Chroma services unless explicitly categorized as an environment-dependent integration test.   | Standard PR suites use fakes/stubs/temp storage and can run reproducibly in CI.                                                                                    | PRD-G-014, PRD-G-036 | [Backend test suite](../../tests/README.md) | **Direct:** suite architecture itself                   |
| **PRD-QA-005** | Parallel backend tests MUST isolate mutable filesystem/SQLite/vector state by worker.                                                                          | pytest-xdist workers do not collide on shared test storage roots.                                                                                                  | PRD-G-032, PRD-G-036 | [Backend test suite](../../tests/README.md) | **Direct:** parallel CI execution                       |

## Requirements traceability requirements

| ID             | Requirement                                                                                                                                  | Acceptance criteria                                                                                                                                    | Parent               | Implementation trace                                             | Verification                                                                                |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| **PRD-QA-016** | Mechanically testable product requirements SHOULD link to one or more validating automated tests.                                            | Requirement tables link the relevant test file/case; absent coverage is labeled Partial/Architectural/Gap instead of implying verification.            | PRD-G-036            | [Requirements index](README.md)                                  | **Direct:** [requirements documentation contracts](../../tests/test_requirements_docs.py)   |
| **PRD-QA-017** | A change that modifies a product invariant SHOULD update both implementation tests and the corresponding requirement documentation.          | PR description/commit can identify affected requirement IDs and changed acceptance criteria where applicable.                                          | PRD-G-036            | [Requirements index](README.md)                                  | **Process:** review gate                                                                    |
| **PRD-QA-018** | Characterization tests MAY preserve existing behavior during refactoring but MUST NOT permanently legitimize known incorrect behavior.       | A deliberate product correction updates characterization baselines and the governing requirement together rather than preserving an obsolete snapshot. | PRD-G-035, PRD-G-039 | [Backend test suite](../../tests/README.md); legacy DOM baseline | **Process/Partial:** [legacy DOM baseline](../../web/tests/e2e/legacy-dom-baseline.spec.ts) |
| **PRD-QA-019** | Flaky tests MUST be fixed or explicitly isolated for a documented environmental reason; markers MUST NOT be used simply to hide instability. | Test taxonomy remains semantic rather than a mechanism for skipping unreliable tests.                                                                  | PRD-G-036            | [Backend test suite](../../tests/README.md)                      | **Process:** CI/review                                                                      |
| **PRD-QA-020** | A release MUST NOT be described as fully validated when required production/Storybook/container builds were not actually run.                | Release notes state what validation was run and what could not be run.                                                                                 | PRD-G-036, PRD-G-037 | [AGENTS](../../AGENTS.md)                                        | **Process/Partial:** [release consistency](../../tests/test_release_consistency.py)         |
