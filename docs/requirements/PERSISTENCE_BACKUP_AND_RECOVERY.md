# Persistence, Backup, Restore, and Recovery Requirements

**Scope:** SQLite/system persistence, corpus/build files, browser-local state, background-job persistence, backup archives, restore validation, Chroma rollback/recovery, and restart behavior.  
**Parent requirements:** [Global requirements](GLOBAL_REQUIREMENTS.md)

## Persistence requirements

| ID              | Requirement                                                                                                                                    | Acceptance criteria                                                                                                                                                          | Parent               | Implementation trace               | Verification                                                                                                 |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| **PRD-BKP-001** | Durable system state MUST survive ordinary application process restart.                                                                        | Provider profiles/settings, annotations/languages, research/provenance data, jobs/history, and other SQLite-backed state reload according to their storage contract.         | PRD-G-032            | [Architecture](../ARCHITECTURE.md) | **Direct:** [SQLite persistence](../../tests/test_sqlite_persistence.py)                                     |
| **PRD-BKP-002** | SQLite writes that update authoritative system/job state MUST be transactional.                                                                | Interrupted writes do not leave partially applied serialized state presented as successful state.                                                                            | PRD-G-032            | persistence contract               | **Direct:** [SQLite persistence](../../tests/test_sqlite_persistence.py)                                     |
| **PRD-BKP-003** | The product MUST distinguish server/corpus persistence from browser-local workspace persistence.                                               | IndexedDB-loaded files/preferences/current local workspace are described and backed up separately from canonical server/corpus state even when one archive can contain both. | PRD-G-003, PRD-G-031 | [User Guide](../USER_GUIDE.md)     | **Partial:** [backup workspace](../../web/tests/frontend/backup-workspace.test.ts); settings/workspace tests |
| **PRD-BKP-004** | Running jobs interrupted by process restart MUST become explicit interrupted/failed history and MUST NOT silently replay.                      | Restart recovery marks in-flight durable job rows failed/interrupted and preserves completed rows.                                                                           | PRD-G-024, PRD-G-032 | job persistence contract           | **Direct:** [SQLite persistence](../../tests/test_sqlite_persistence.py)                                     |
| **PRD-BKP-005** | Derived stores SHOULD carry enough manifest/identity information to determine when they are stale relative to their canonical source snapshot. | Vector/benchmark/derived data can detect source/index drift or require rebuild instead of being treated as current by default.                                               | PRD-G-014, PRD-G-032 | [Architecture](../ARCHITECTURE.md) | **Direct/Partial:** [pipeline benchmark](../../tests/test_pipeline_benchmark.py); Chroma store/vector tests  |

## Backup requirements

| ID              | Requirement                                                                                                                                                 | Acceptance criteria                                                                                                              | Parent               | Implementation trace                                        | Verification                                                                      |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | -------------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------------- |
| **PRD-BKP-006** | A full backup MUST identify itself with a typed/versioned manifest sufficient to reject unrelated archives.                                                 | Restore checks `backup_type`/version and required members before destructive replacement.                                        | PRD-G-032            | [User Guide](../USER_GUIDE.md)                              | **Partial:** admin backup/restore implementation; legacy backup E2E states        |
| **PRD-BKP-007** | Backup creation MUST be blocked while background operations can make the archive internally inconsistent.                                                   | Active jobs prevent full-backup restore and, where required by implementation, backup creation until work is cancelled/finished. | PRD-G-024, PRD-G-032 | [User Guide](../USER_GUIDE.md)                              | **Direct:** [backup workspace](../../web/tests/frontend/backup-workspace.test.ts) |
| **PRD-BKP-008** | Backup UI MUST disclose when provider credentials will be included.                                                                                         | Confirmation reflects secret-bearing provider profiles and does not imply the archive is safe to share.                          | PRD-G-018, PRD-G-023 | backup UX contract                                          | **Direct:** [backup workspace](../../web/tests/frontend/backup-workspace.test.ts) |
| **PRD-BKP-009** | Backup archive construction MUST remain bounded to the host-mounted data area for large data rather than depending on ephemeral container overlay capacity. | Large archive assembly uses the configured durable data root.                                                                    | PRD-G-032, PRD-G-033 | [User Guide](../USER_GUIDE.md)                              | **Architectural/Partial:** backup implementation review                           |
| **PRD-BKP-010** | Persisted benchmark cases/runs and other new durable subsystems MUST participate in backup/restore when the product claims full-backup coverage.            | Referential integrity between restored benchmark run and immutable case is validated.                                            | PRD-G-014, PRD-G-032 | [PR #286](https://github.com/ajschlosser/DerridAI/pull/286) | **Direct:** [pipeline benchmark](../../tests/test_pipeline_benchmark.py)          |

## Restore/recovery requirements

| ID              | Requirement                                                                                                             | Acceptance criteria                                                                                                                                     | Parent               | Implementation trace           | Verification                                                                                                 |
| --------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| **PRD-BKP-011** | Restore MUST validate ZIP member paths before extraction.                                                               | Absolute/path-traversal/unsafe members are rejected and cannot write outside the intended restore root.                                                 | PRD-G-018, PRD-G-032 | [User Guide](../USER_GUIDE.md) | **Partial:** admin restore implementation; dedicated archive-safety test should remain/add explicit coverage |
| **PRD-BKP-012** | Restore MUST validate the archive manifest before replacing current state.                                              | Non-DerridAI/wrong-type/incompatible backup archives fail before destructive apply.                                                                     | PRD-G-032, PRD-G-039 | [User Guide](../USER_GUIDE.md) | **Partial:** admin restore implementation; backup workflow/E2E coverage                                      |
| **PRD-BKP-013** | Chroma restore MUST protect the current vector database with a rollback path if applying the backup fails.              | Before replacement, current logical Chroma state is snapshotted; failure restores that snapshot rather than leaving a half-restored vector store.       | PRD-G-032            | [User Guide](../USER_GUIDE.md) | **Partial:** Chroma backup/restore implementation; add/maintain dedicated failure-injection coverage         |
| **PRD-BKP-014** | Restore MUST not proceed while active background operations could write into state being replaced.                      | UI/backend guard refuses restore until active operations are finished/cancelled.                                                                        | PRD-G-024, PRD-G-032 | [User Guide](../USER_GUIDE.md) | **Direct:** [backup workspace](../../web/tests/frontend/backup-workspace.test.ts)                            |
| **PRD-BKP-015** | Successful full restore MUST reconcile server state and browser-local workspace state according to the backup contract. | After server restore succeeds, included browser workspace/current source state is replaced and UI reload/resync occurs; omitted data is not fabricated. | PRD-G-032            | [User Guide](../USER_GUIDE.md) | **Partial:** legacy backup/restore E2E states                                                                |
| **PRD-BKP-016** | Restore errors MUST leave the product in a known recoverable state and MUST be surfaced to the user.                    | Failure does not report success; rollback/recovery status and next action are visible.                                                                  | PRD-G-025, PRD-G-032 | backup/recovery contract       | **Partial:** failure visibility + backup workflow tests                                                      |
