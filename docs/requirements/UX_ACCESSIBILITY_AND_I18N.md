# Application Shell, UX, Accessibility, and Internationalization Requirements

**Scope:** Application shell, information architecture, routes, shared workspace behavior, visual system, Help Center, accessibility, responsive behavior, and locale support.  
**Parent requirements:** [Global requirements](GLOBAL_REQUIREMENTS.md)

## Shared UX requirements

| ID             | Requirement                                                                                                                                                       | Acceptance criteria                                                                                                                                                              | Parent                 | Implementation trace                                                                        | Verification                                                                                                                                                                                                               |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- | ------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **PRD-UX-001** | Dense data workspaces SHOULD share consistent conventions for sorting, filtering, selection, columns, density, pagination, status, and empty/loading/error state. | Users do not need to relearn basic table/data-workspace behavior between Records, Search, Works, Users/Roles, Vector Stores, and System Data without a documented domain reason. | PRD-G-021              | [User Guide](../USER_GUIDE.md)                                                              | **Partial:** [Records view](../../web/tests/frontend/records-view.test.ts); [Records workspace](../../web/tests/frontend/records-workspace.test.ts); [Search workspace](../../web/tests/frontend/search-workspace.test.ts) |
| **PRD-UX-002** | Progressive disclosure MUST reduce visual complexity without hiding errors, uncertainty, authority, or evidence state required for a user decision.               | Capacity/advanced provider settings and deep diagnostics can collapse; consequential status remains visible at the decision point.                                               | PRD-G-022              | [PR #282](https://github.com/ajschlosser/DerridAI/pull/282); [User Guide](../USER_GUIDE.md) | **Partial:** [Providers view](../../web/tests/frontend/providers-view.test.ts)                                                                                                                                             |
| **PRD-UX-003** | Consequential controls MUST explain downstream effects in plain language.                                                                                         | Where applicable, copy explains what changes, what becomes stale, reversibility, and whether authoritative or only derived state is affected.                                    | PRD-G-023              | [PR #288](https://github.com/ajschlosser/DerridAI/pull/288)                                 | **Partial:** [Help Center](../../web/tests/frontend/help-center.test.ts); [Help Center view](../../web/tests/frontend/help-center-view.test.ts)                                                                            |
| **PRD-UX-004** | Status presentation MUST be semantically meaningful and MUST NOT depend on color alone.                                                                           | Status has readable text and/or icon/shape/accessibility semantics; success/error/warning/neutral styling maps to shared tokens.                                                 | PRD-G-026, PRD-G-029   | [Design Tokens](../DESIGN_TOKENS.md)                                                        | **Direct/Partial:** [design tokens](../../web/tests/frontend/design-tokens.test.ts); WCAG E2E tests                                                                                                                        |
| **PRD-UX-005** | Shared visual design MUST use semantic design tokens rather than page-specific literal colors for standard surfaces/status/focus behavior.                        | Theme changes preserve semantic roles and contrast; components render consistently across light/dark/high-contrast states.                                                       | PRD-G-029              | [Design Tokens](../DESIGN_TOKENS.md)                                                        | **Direct:** [design tokens](../../web/tests/frontend/design-tokens.test.ts)                                                                                                                                                |
| **PRD-UX-006** | Reusable UI patterns SHOULD be components/primitives with Storybook coverage where that reduces meaningful duplication.                                           | Common controls/data-workspace elements are not repeatedly reimplemented with diverging semantics.                                                                               | PRD-G-035, PRD-G-036   | [Contributing](../../CONTRIBUTING.md)                                                       | **Architectural/Partial:** Storybook build and component tests                                                                                                                                                             |
| **PRD-UX-007** | Narrow-screen adaptations MUST preserve the user's ability to complete the core task.                                                                             | Tables/dialogs/cards may scroll, stack, or collapse but critical actions/state remain available and accessible.                                                                  | PRD-G-028              | product UX                                                                                  | **Partial:** [app views](../../web/tests/e2e/app-views.spec.ts); [records-dialog a11y](../../web/tests/e2e/records-dialogs-a11y.spec.ts)                                                                                   |
| **PRD-UX-008** | Empty, loading, error, unavailable, and no-result states MUST be distinct where they imply different next actions.                                                | UI does not use an empty table to represent loading or provider failure; actionable recovery guidance is shown when appropriate.                                                 | PRD-G-025, PRD-NFR-001 | product UX                                                                                  | **Partial:** area-specific frontend tests                                                                                                                                                                                  |
