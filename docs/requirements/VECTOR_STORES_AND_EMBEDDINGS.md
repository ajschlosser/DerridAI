# Vector Store and Embedding Requirements

**Scope:** Chroma connection modes, vector collection identity, embeddings, language mirrors, upserts, System Chroma administration, derived-state authority, and round-trip behavior.  
**Parent requirements:** [Global requirements](GLOBAL_REQUIREMENTS.md)

## Vector-store requirements

| ID | Requirement | Acceptance criteria | Parent | Implementation trace | Verification |
| --- | --- | --- | --- | --- | --- |
| **PRD-VEC-001** | Vector stores MUST be treated as derived/rebuildable search projections rather than authoritative corpus storage. | Deleting/rebuilding a Chroma collection does not redefine Record/FieldAssertion/source authority. UI and documentation describe vector data as derived. | PRD-G-003, PRD-G-040 | [Architecture](../ARCHITECTURE.md); [README](../../README.md) | **Partial:** [semantic-map provenance](../../tests/test_record_semantic_map_provenance.py); [System Data baseline](../../web/tests/e2e/legacy-dom-baseline.spec.ts) |
| **PRD-VEC-002** | DerridAI MUST support deliberate embedded-filesystem and HTTP-server Chroma connection modes. | Connection identity/configuration distinguishes PersistentClient/local path from HTTP endpoint/server mode; changing mode does not imply automatic data migration. | PRD-G-015, PRD-G-031 | [User Guide](../USER_GUIDE.md) | **Direct:** [Chroma connection](../../tests/test_chroma_connection.py) |
| **PRD-VEC-003** | Embedded Chroma storage MUST avoid unsupported multi-writer assumptions. | Product architecture does not point multiple independent writers at the same embedded persistence directory; HTTP mode is used for a shared server. | PRD-G-032, PRD-G-033 | [Architecture](../ARCHITECTURE.md) | **Direct/Partial:** [Chroma connection](../../tests/test_chroma_connection.py) |
| **PRD-VEC-004** | Chroma HTTP endpoint configuration MUST reject malformed/relative/credential-bearing URLs and keep authentication material in dedicated secret fields. | URL parsing requires an absolute endpoint origin; embedded URL credentials are rejected; public configuration does not echo secrets. | PRD-G-018, PRD-NFR-003 | Chroma connection contract | **Direct:** [Chroma connection](../../tests/test_chroma_connection.py) |
| **PRD-VEC-005** | Vector collection names MUST be validated before storage operations. | Invalid Chroma names, including too-short, IP-shaped, or space-containing names, fail API schema validation. | PRD-G-011 | API vector contract | **Direct:** [collection-name schema](../../tests/test_collection_name_schema.py) |
| **PRD-VEC-006** | New collection defaults MUST use the documented retrieval/distance contract unless the user explicitly chooses otherwise. | Default retrieval mode and distance metric remain stable/visible and changes are intentional/versioned product behavior. | PRD-G-014, PRD-G-023 | API vector contract | **Direct:** [collection-name schema](../../tests/test_collection_name_schema.py) |
| **PRD-VEC-007** | Researcher access to vector-store data MUST obey corpus/read permissions and response text policy. | Hidden/system/cache collections are not exposed to researchers; permitted Record projections are filtered according to researcher policy. | PRD-G-018 | GraphQL/vector access contract | **Direct:** [GraphQL record reads](../../tests/test_graphql_record_reads.py) |
| **PRD-VEC-008** | System/internal collections MUST be distinguishable from user corpus collections. | System collection metadata/identity prevents internal caches/exemplars from appearing as ordinary corpora in researcher-facing selectors. | PRD-G-003, PRD-G-018 | System Data/vector architecture | **Direct/Partial:** [system metadata exemplars](../../tests/test_system_metadata_exemplars.py); [GraphQL record reads](../../tests/test_graphql_record_reads.py) |
| **PRD-VEC-009** | Upsert synchronization MUST be resumable/incremental and MUST identify pending/stale derived state rather than silently claiming synchronization. | Failed/interrupted batches can be retried; fingerprints/receipts or equivalent state prevent unnecessary complete rewrites and expose pending work. | PRD-G-024, PRD-G-025, PRD-G-033 | [User Guide](../USER_GUIDE.md) | **Partial:** upsert job and vector-store frontend tests |
| **PRD-VEC-010** | Switching Chroma connection mode or embedding defaults MUST NOT silently move/reinterpret existing collections. | UI explains that collections remain where they were created and that changed embedding contracts may require rebuilding derived collections. | PRD-G-023, PRD-G-032 | [User Guide](../USER_GUIDE.md) | **Partial:** [Chroma connection](../../tests/test_chroma_connection.py); settings/vector-store frontend tests |
| **PRD-VEC-011** | Destructive HTTP-server reset behavior MUST target the configured server and MUST NOT wipe an unrelated local embedded data directory. | Server-mode NUKE deletes appropriate server collections without treating local `./data/chroma` as the active store. | PRD-G-018, PRD-G-032 | Chroma connection contract | **Direct:** [Chroma connection](../../tests/test_chroma_connection.py) |

## Embedding requirements

| ID | Requirement | Acceptance criteria | Parent | Implementation trace | Verification |
| --- | --- | --- | --- | --- | --- |
| **PRD-VEC-012** | Embedding execution MUST be provider/profile independent at the scholarly layer. | Ollama/local and configured provider-profile embedding backends produce the same abstract embedding contract without changing Record authority semantics. | PRD-G-015 | [README](../../README.md) | **Direct:** [Chroma embedding profiles](../../tests/test_chroma_embedding_profiles.py) |
| **PRD-VEC-013** | A vector collection MUST retain enough embedding identity/configuration to detect incompatible reuse. | Provider/model/dimension or equivalent build contract is available for validation/rebuild decisions. | PRD-G-014, PRD-G-032 | [User Guide](../USER_GUIDE.md) | **Direct/Partial:** [Chroma embedding profiles](../../tests/test_chroma_embedding_profiles.py); SQLite/vector persistence tests |
| **PRD-VEC-014** | Language-specific collections/mirrors MUST be deterministic derived projections of eligible source Records. | Regional variants route to supported language identities; primary/general/language mirrors do not create new scholarly Records. | PRD-G-003, PRD-G-008 | [User Guide](../USER_GUIDE.md) | **Partial:** language identity/routing tests; vector-store integration tests |
| **PRD-VEC-015** | Embedding/vector failures MUST degrade search explicitly and MUST NOT alter canonical corpus state. | Search/retrieval can report vector unavailability/fallback while authoritative Records remain intact. | PRD-G-025, PRD-G-033 | retrieval architecture | **Direct/Partial:** [progressive metadata retrieval](../../tests/test_progressive_metadata_retrieval.py); [research memory](../../tests/test_research_memory.py) |
