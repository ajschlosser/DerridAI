# Operations, Background Jobs, and Realtime Requirements

**Scope:** Background job lifecycle, cancellation, durable history, restart behavior, Operations UI, WebSocket notifications, polling fallback, and ephemeral live hints.  
**Parent requirements:** [Global requirements](GLOBAL_REQUIREMENTS.md)

## Background-job requirements

| ID              | Requirement                                                                                                                                                                                                  | Acceptance criteria                                                                                                                                                           | Parent                          | Implementation trace                                               | Verification                                                                                                                                                    |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- | ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **PRD-OPS-001** | Long-running LLM review, Research, tools, capture/build, and vector upsert work SHOULD execute through explicit background-operation contracts when foreground execution would block normal application use. | The initiating workspace remains usable/navigable where safe; the operation is represented in centralized job state.                                                          | PRD-G-024                       | [Architecture](../ARCHITECTURE.md); [User Guide](../USER_GUIDE.md) | **Partial:** [jobs workspace](../../web/tests/frontend/jobs-workspace.test.ts); [operations panel](../../web/tests/frontend/operations-panel.test.ts)           |
| **PRD-OPS-002** | Jobs MUST expose a truthful lifecycle including queued, running, cancelling, completed, cancelled, and failed states where applicable.                                                                       | UI/API do not collapse `cancelling` into `cancelled` before work has stopped and do not label a failed operation completed.                                                   | PRD-G-024, PRD-G-025            | [User Guide](../USER_GUIDE.md)                                     | **Direct/Partial:** [operations panel E2E](../../web/tests/e2e/operations-panel.spec.ts); [SQLite persistence](../../tests/test_sqlite_persistence.py)          |
| **PRD-OPS-003** | Cancellation semantics MUST match the underlying operation's safe interruption boundary.                                                                                                                     | Queued work can cancel immediately; streamed generation can interrupt where supported; retrieval/reranking/upsert stop at documented checkpoints/batch boundaries.            | PRD-G-024, PRD-G-033            | [User Guide](../USER_GUIDE.md)                                     | **Partial:** job-manager/backend tests; [operations panel E2E](../../web/tests/e2e/operations-panel.spec.ts)                                                    |
| **PRD-OPS-004** | Job status MUST expose enough context for a user to understand what is running and what happened without exposing secrets.                                                                                   | Applicable job details include type, provider/model/target, progress/stage/current item, elapsed time, failures, timeline, and result/next action; secret values are omitted. | PRD-G-023, PRD-G-024, PRD-G-031 | [User Guide](../USER_GUIDE.md)                                     | **Direct/Partial:** [operations panel](../../web/tests/frontend/operations-panel.test.ts); [operations panel E2E](../../web/tests/e2e/operations-panel.spec.ts) |
| **PRD-OPS-005** | Durable job history MUST survive ordinary process restart; work interrupted by restart MUST be marked failed rather than silently replayed.                                                                  | Restarted job repository identifies previously running work as interrupted/failed and preserves completed history.                                                            | PRD-G-032                       | persistence/job contract                                           | **Direct:** [SQLite persistence](../../tests/test_sqlite_persistence.py)                                                                                        |
| **PRD-OPS-006** | A failure to write/update durable job state that could change user-visible operation truth MUST surface rather than being swallowed.                                                                         | Storage failure produces an operation error/warning and cannot leave the product falsely reporting success.                                                                   | PRD-G-025, PRD-G-032            | failure contract                                                   | **Direct:** [failure visibility](../../tests/test_failure_visibility.py)                                                                                        |
| **PRD-OPS-007** | Operations UI MUST remain usable by keyboard and assistive technology.                                                                                                                                       | Running rows expose named progressbars and row-specific Cancel controls; status changes are announced appropriately; text spacing/reflow does not hide controls.              | PRD-G-026                       | accessibility contract                                             | **Direct:** [operations panel E2E](../../web/tests/e2e/operations-panel.spec.ts)                                                                                |
| **PRD-OPS-008** | Finished-job removal/clearing MUST affect history presentation without mutating canonical research/corpus results produced by those jobs.                                                                    | Clearing an Operations row is not equivalent to deleting the output corpus/response/vector collection.                                                                        | PRD-G-003                       | operations contract                                                | **Partial:** operations panel/workspace regression tests                                                                                                        |

## Realtime requirements

| ID              | Requirement                                                                                                                                                                   | Acceptance criteria                                                                                                                                                                                                                                                                                   | Parent                          | Implementation trace                                                                                                                                                                                                                                         | Verification                                                                                                                                                                                                                                   |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **PRD-OPS-009** | Realtime WebSocket updates MUST be an optimization/notification plane rather than the authoritative storage layer.                                                            | Loss/failure of the socket does not fail the underlying job; clients can resynchronize canonical state from REST/GraphQL where documented.                                                                                                                                                            | PRD-G-003, PRD-G-033            | [Realtime](../REALTIME.md); [Architecture](../ARCHITECTURE.md)                                                                                                                                                                                               | **Direct:** [realtime plane](../../tests/test_realtime_plane.py)                                                                                                                                                                               |
| **PRD-OPS-010** | Realtime connections and subscriptions MUST authenticate and authorize per topic/audience.                                                                                    | Unauthorized subscriptions are refused and user-scoped events are not delivered to other users.                                                                                                                                                                                                       | PRD-G-018                       | [Realtime](../REALTIME.md)                                                                                                                                                                                                                                   | **Direct:** [realtime plane](../../tests/test_realtime_plane.py)                                                                                                                                                                               |
| **PRD-OPS-011** | Realtime delivery MUST remain bounded under slow/disconnected clients.                                                                                                        | Outgoing queues have finite bounds/coalescing behavior so one slow browser cannot create unbounded memory growth.                                                                                                                                                                                     | PRD-G-033                       | [Realtime](../REALTIME.md)                                                                                                                                                                                                                                   | **Direct:** [realtime plane](../../tests/test_realtime_plane.py)                                                                                                                                                                               |
| **PRD-OPS-012** | Reconnect behavior MUST either replay a bounded eligible event window or explicitly resynchronize canonical state; ephemeral events MUST NOT be replayed as if durable.       | Reconnection cannot turn transient model text/progress hints into historical authoritative events.                                                                                                                                                                                                    | PRD-G-003, PRD-G-032            | [Realtime](../REALTIME.md)                                                                                                                                                                                                                                   | **Direct:** [realtime plane](../../tests/test_realtime_plane.py); [realtime live hints](../../tests/test_realtime_live_hints.py)                                                                                                               |
| **PRD-OPS-013** | Ephemeral live hints MUST be text/privacy bounded and MUST NOT carry source evidence or become canonical corpus state.                                                        | Draft generation deltas/per-record progress use bounded buffers/rings/dedup and omit source/evidence text prohibited by the event contract.                                                                                                                                                           | PRD-G-002, PRD-G-003, PRD-G-018 | [Realtime](../REALTIME.md)                                                                                                                                                                                                                                   | **Direct:** [realtime live hints](../../tests/test_realtime_live_hints.py)                                                                                                                                                                     |
| **PRD-OPS-014** | When realtime is unavailable, supported views SHOULD fall back to bounded polling/resync rather than becoming stale without explanation.                                      | Jobs/corpus status continue to update at the documented fallback cadence and the user can manually refresh.                                                                                                                                                                                           | PRD-G-024, PRD-G-025            | [User Guide](../USER_GUIDE.md); [Realtime](../REALTIME.md)                                                                                                                                                                                                   | **Partial:** [jobs workspace](../../web/tests/frontend/jobs-workspace.test.ts); app workflow tests                                                                                                                                             |
| **PRD-OPS-015** | Realtime event publication failure MUST NOT alter the success/failure of the underlying durable operation.                                                                    | A job can complete and remain queryable even if a notification cannot be delivered.                                                                                                                                                                                                                   | PRD-G-003, PRD-G-033            | [Realtime](../REALTIME.md)                                                                                                                                                                                                                                   | **Direct:** [realtime plane](../../tests/test_realtime_plane.py)                                                                                                                                                                               |
| **PRD-OPS-016** | Mutable page-data resources SHOULD refresh through the shared authenticated `resource.changed` invalidation plane instead of page-specific polling or manual reload controls. | Domain mutations publish a coalescable resource key only after the canonical commit; mounted shared data queries invalidate on that event, all data queries invalidate on realtime resync, and new page-specific `setInterval` polling outside the realtime layer is rejected by regression coverage. | PRD-G-003, PRD-G-024, PRD-G-033 | [Realtime](../REALTIME.md); [PR #364](https://github.com/ajschlosser/DerridAI/pull/364)                                                                                                                                                                      | **Direct:** [realtime resources](../../tests/test_realtime_resources.py); [realtime data bridge](../../web/tests/frontend/realtime-data-bridge.test.ts); [realtime polling ratchet](../../web/tests/frontend/realtime-polling-ratchet.test.ts) |
| **PRD-OPS-017** | Streamed/live Research text and other realtime hints MUST remain advisory until the canonical completed result is read from the authoritative API.                            | A running draft may update the workspace without being stored or cited as the final answer; completion/failure causes the client to reconcile from durable REST/GraphQL state, and losing an ephemeral hint does not alter the operation result.                                                      | PRD-G-003, PRD-G-013, PRD-G-024 | [CORE-ID-005](../../SPECIFICATION.md#normative-conformance-requirement-catalogue); [CLM-ID-002](../../SPECIFICATION.md#normative-conformance-requirement-catalogue); [Realtime](../REALTIME.md); [PR #360](https://github.com/ajschlosser/DerridAI/pull/360) | **Direct/Partial:** [realtime live hints](../../tests/test_realtime_live_hints.py); [Research progressive loading](../../web/tests/frontend/research-progressive-loading.test.ts); [realtime plane](../../tests/test_realtime_plane.py)        |
