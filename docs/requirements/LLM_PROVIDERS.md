# LLM Provider and Model Configuration Requirements

**Scope:** Provider profiles, Ollama/OpenAI-compatible backends, provider selection, model discovery, warmup, generation parameters, concurrency, credentials, embedding profiles, and degraded-state behavior.  
**Parent requirements:** [Global requirements](GLOBAL_REQUIREMENTS.md)

## Requirements

| ID              | Requirement                                                                                                                                            | Acceptance criteria                                                                                                                                                | Parent                 | Implementation trace                                        | Verification                                                                                                                                                                                                     |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------- | ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **PRD-LLM-001** | LLM integration MUST use named provider profiles rather than assuming one global model endpoint.                                                       | Multiple Ollama/OpenAI-compatible profiles may coexist with independent endpoint/model/settings/concurrency/warmup state.                                          | PRD-G-015, PRD-G-035   | [User Guide](../USER_GUIDE.md)                              | **Direct/Partial:** [provider-profiles service](../../web/tests/frontend/provider-profiles-service.test.ts); [Corpus enrichment configuration](../../web/tests/frontend/corpus-enrichment-configuration.test.ts) |
| **PRD-LLM-002** | Provider type MUST remain abstracted from scholarly workflows.                                                                                         | Research, review, enrichment, tools, and embeddings select a profile/capability without changing FieldAssertion/evidence/authority semantics based on vendor.      | PRD-G-015, PRD-G-040   | [Architecture](../ARCHITECTURE.md)                          | **Direct/Partial:** provider-profile frontend tests; [Chroma embedding profiles](../../tests/test_chroma_embedding_profiles.py)                                                                                  |
| **PRD-LLM-003** | Provider credentials MUST be handled as secrets and MUST NOT be persisted into corpus build/audit metadata or ordinary shareable URL state.            | API keys do not appear in build request snapshots, provenance logs, public provider config, or shareable route state.                                              | PRD-G-018, PRD-NFR-003 | provider security contract                                  | **Direct/Partial:** [editorial memory/provider switch](../../tests/test_editorial_memory_and_provider_switch.py); [Corpus provider credentials](../../tests/test_corpus_provider_credentials.py)                 |
| **PRD-LLM-004** | A browser-supplied request credential MUST NOT be silently replaced with a different stored credential when the request intentionally provides one.    | Provider resolution preserves the explicit request endpoint/key/model; blank credentials may fall back to the stored profile according to the documented contract. | PRD-G-018, PRD-G-023   | provider resolution contract                                | **Direct:** [Corpus provider credentials](../../tests/test_corpus_provider_credentials.py)                                                                                                                       |
| **PRD-LLM-005** | Changing provider/model during an in-progress corpus workflow MUST be auditable and secret-safe.                                                       | The build records provider/model/profile identity needed for reproducibility but does not persist secret values.                                                   | PRD-G-014, PRD-G-018   | [User Guide](../USER_GUIDE.md)                              | **Direct:** [editorial memory/provider switch](../../tests/test_editorial_memory_and_provider_switch.py)                                                                                                         |
| **PRD-LLM-006** | Provider profiles SHOULD expose connection/model testing before consequential runs.                                                                    | User can test endpoint/model availability and receives a clear success/failure result without beginning a corpus/Research mutation.                                | PRD-G-023, PRD-G-025   | [User Guide](../USER_GUIDE.md)                              | **Partial:** provider-profile service/view tests                                                                                                                                                                 |
| **PRD-LLM-007** | Model discovery MUST remain advisory configuration data and MUST NOT automatically change the selected production model.                               | Discovered models populate choices; the user/system explicitly selects/saves a model before defaults change.                                                       | PRD-G-023, PRD-G-031   | [User Guide](../USER_GUIDE.md)                              | **Direct/Partial:** [provider-profiles service](../../web/tests/frontend/provider-profiles-service.test.ts)                                                                                                      |
| **PRD-LLM-008** | Warmup MUST be represented as provider/model operational state rather than scholarly state.                                                            | Warmup success/failure affects readiness indicators and scheduling, not Record/claim authority.                                                                    | PRD-G-003, PRD-G-024   | [User Guide](../USER_GUIDE.md)                              | **Direct/Partial:** [provider-profiles service](../../web/tests/frontend/provider-profiles-service.test.ts)                                                                                                      |
| **PRD-LLM-009** | Per-profile concurrency MUST bound simultaneous provider calls where configured.                                                                       | Scheduling honors profile-specific concurrency limits so one workflow cannot exceed the profile contract or starve unrelated profiles without explicit policy.     | PRD-G-024, PRD-G-033   | [User Guide](../USER_GUIDE.md)                              | **Partial:** job/provider concurrency tests                                                                                                                                                                      |
| **PRD-LLM-010** | Provider/model unavailability MUST be exposed explicitly and MUST NOT be converted into a false “no scholarly value found” result.                     | Operational provider failure is distinct from a model-evaluated absence/unsupported value.                                                                         | PRD-G-025              | provider/enrichment contract                                | **Partial:** [failure visibility](../../tests/test_failure_visibility.py); enrichment/provider tests                                                                                                             |
| **PRD-LLM-011** | Built-in prompts MUST remain corpus-neutral and MAY consume runtime documentary metadata.                                                              | Prompts may reference supplied `document_author`/schema guidance but do not hard-code a particular author/work as universal authority.                             | PRD-G-006, PRD-G-008   | [PR #268](https://github.com/ajschlosser/DerridAI/pull/268) | **Direct:** [prompt author neutrality](../../tests/test_prompt_author_neutrality.py)                                                                                                                             |
| **PRD-LLM-012** | Provider-profile UI MUST distinguish saved state from unsaved edits and SHOULD support explicit save/discard.                                          | Unsaved endpoint/model/parameter changes are not represented as active persisted configuration until saved.                                                        | PRD-G-023, PRD-G-031   | [User Guide](../USER_GUIDE.md)                              | **Direct/Partial:** [provider-profiles service](../../web/tests/frontend/provider-profiles-service.test.ts); [Providers view](../../web/tests/frontend/providers-view.test.ts)                                   |
| **PRD-LLM-013** | Administrative provider detail MAY be richer than researcher-visible provider selection, but capability boundaries MUST remain enforced by the server. | Researcher can select allowed profiles/options without gaining access to secrets/internal administrative configuration.                                            | PRD-G-018              | security/provider contract                                  | **Partial:** [researcher route policy](../../tests/test_researcher_route_policy.py); researcher profile tests                                                                                                    |
