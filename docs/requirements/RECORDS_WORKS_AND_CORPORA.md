# Records, Works, and Corpus Management Requirements

**Scope:** Records workspace, Record Inspector, Works, corpus-level management, subsets, bulk operations, semantic maps, and derived corpus views.  
**Parent requirements:** [Global requirements](GLOBAL_REQUIREMENTS.md)

## Record requirements

| ID              | Requirement                                                                                                                                                | Acceptance criteria                                                                                                                                                           | Parent               | Implementation trace                                                  | Verification                                                                                                                                                                                                             |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **PRD-REC-001** | The Records workspace MUST treat the published/loaded Record as a scholarly object rather than merely a table row.                                         | Opening a row provides Record text, bibliographic context, metadata/assertions, provenance, evidence/audit links, and applicable revision/review state.                       | PRD-G-001, PRD-G-002 | [User Guide](../USER_GUIDE.md); [cELF Record](../../SPECIFICATION.md) | **Partial:** [Records view](../../web/tests/frontend/records-view.test.ts); [Record workspace](../../web/tests/frontend/record-workspace.test.ts); [inspector layout](../../web/tests/frontend/inspector-layout.test.ts) |
| **PRD-REC-002** | Record Inspector MUST discover schema-defined scholarly fields through generic assertion/schema contracts.                                                 | Custom assertion fields can appear in the inspector without being added to a fixed hard-coded field catalog.                                                                  | PRD-G-007, PRD-G-035 | [FieldAssertion migration](../FIELD_ASSERTION_MIGRATION.md)           | **Direct:** [inspector layout](../../web/tests/frontend/inspector-layout.test.ts) (`discovers custom assertion fields without adding them to the hard-coded catalog`)                                                    |
| **PRD-REC-003** | Record views MUST preserve the distinction between materialized field values, assertion provenance/authority, indexing diagnostics, and source provenance. | Inspector grouping and labels do not flatten model/human provenance or derived indexing data into one metadata list.                                                          | PRD-G-003, PRD-G-004 | [cELF](../../SPECIFICATION.md)                                        | **Direct/Partial:** [inspector layout](../../web/tests/frontend/inspector-layout.test.ts); [FieldAssertion frontend](../../web/tests/frontend/field-assertions-domain.test.ts)                                           |
| **PRD-REC-004** | Records workspace state SHOULD be addressable and restorable through safe URL state.                                                                       | Search/filter/sort/page/column/density state that is useful to share is restored through browser history and copied URLs.                                                     | PRD-G-020, PRD-G-021 | [PR #284](https://github.com/ajschlosser/DerridAI/pull/284)           | **Direct:** [Records workspace](../../web/tests/frontend/records-workspace.test.ts)                                                                                                                                      |
| **PRD-REC-005** | Record table operations MUST preserve stable `record_id` identity across sorting, filtering, pagination, file loading, and vector synchronization.         | UI row position or Chroma ID never substitutes for the Record's logical identity.                                                                                             | PRD-G-009            | [cELF Record identity](../../SPECIFICATION.md)                        | **Partial:** [Records view](../../web/tests/frontend/records-view.test.ts); [research object graph](../../tests/test_research_object_graph.py)                                                                           |
| **PRD-REC-006** | Record-level bulk operations MUST apply through the same validation/authority contracts as equivalent single-Record operations.                            | Bulk edits cannot bypass schema validation, human ownership, evidence requirements, or audit history.                                                                         | PRD-G-005, PRD-G-007 | [User Guide](../USER_GUIDE.md)                                        | **Direct/Partial:** [metadata batch decisions](../../tests/test_metadata_batch_decisions.py); [work-wide metadata](../../tests/test_work_wide_metadata.py)                                                               |
| **PRD-REC-007** | Record views MUST expose source/evidence navigation when resolvable provenance exists.                                                                     | Users can move from a Record to its source context/evidence without inferring the source from display text alone.                                                             | PRD-G-002, PRD-G-013 | [cELF reverse audit path](../../SPECIFICATION.md)                     | **Partial:** [record traceability explorer](../../web/tests/frontend/record-traceability-explorer.test.ts); [research object graph](../../tests/test_research_object_graph.py)                                           |
| **PRD-REC-008** | A Record revision that invalidates a support/evidence relationship MUST NOT continue to present that binding as current.                                   | Current/stale binding status is distinguishable in Record-related views and APIs.                                                                                             | PRD-G-009, PRD-G-013 | [cELF revisions/support bindings](../../SPECIFICATION.md)             | **Partial:** [corpus precedents](../../web/tests/frontend/corpus-precedents.test.ts); [review decisions](../../tests/test_review_decisions.py)                                                                           |
| **PRD-REC-009** | Record view rendering MUST remain usable with schema evolution.                                                                                            | Unknown/custom scholarly assertion fields are rendered generically where possible; missing historical schema metadata degrades explicitly rather than crashing the inspector. | PRD-G-007, PRD-G-039 | [FieldAssertion migration](../FIELD_ASSERTION_MIGRATION.md)           | **Partial:** [inspector layout](../../web/tests/frontend/inspector-layout.test.ts); [metadata schema](../../tests/test_metadata_schema.py)                                                                               |

## Works requirements

| ID              | Requirement                                                                                                                      | Acceptance criteria                                                                                                                            | Parent               | Implementation trace                       | Verification                                                                                                                               |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **PRD-WRK-001** | Works MUST aggregate Records by canonical work identity/title without replacing Record-level authority.                          | Work summaries derive counts/facets from constituent Records while preserving the ability to inspect the underlying Records.                   | PRD-G-003, PRD-G-040 | [User Guide](../USER_GUIDE.md)             | **Direct/Partial:** [Works view](../../web/tests/frontend/works-view.test.ts); [Works E2E](../../web/tests/e2e/works.spec.ts)              |
| **PRD-WRK-002** | Work/corpus-scoped metadata edits MUST validate against the active schema and field scope.                                       | Unknown fields or invalid values are rejected; corpus/work-scoped fields apply only at the configured scope.                                   | PRD-G-007            | [Metadata Schemas](../METADATA_SCHEMAS.md) | **Direct:** [work-wide metadata](../../tests/test_work_wide_metadata.py); [metadata field scope](../../tests/test_metadata_field_scope.py) |
| **PRD-WRK-003** | Work-level human edits MUST establish human authority and survive concurrent/next enrichment passes.                             | Editing a work/manifest field while enrichment runs saves the decision and automatic enrichment does not silently overwrite it.                | PRD-G-005, PRD-G-024 | [User Guide](../USER_GUIDE.md)             | **Direct:** [human metadata ownership](../../tests/test_human_metadata_ownership.py); [manifest edits](../../tests/test_manifest_edits.py) |
| **PRD-WRK-004** | Works MUST expose incomplete/review-relevant state in a way that leads to the underlying Records requiring action.               | Work metrics do not claim completeness when required Records/fields are unresolved; review actions can open the relevant Record subset.        | PRD-G-023, PRD-G-025 | [User Guide](../USER_GUIDE.md)             | **Partial:** [Works view](../../web/tests/frontend/works-view.test.ts); [review queues](../../tests/test_review_queues.py)                 |
| **PRD-WRK-005** | Work-level semantic/derived visualizations MUST remain explicitly derived and traceable to the build/Records that produced them. | A published Work can resolve its originating build for a semantic map without embedding build-operational state into the public Record itself. | PRD-G-003, PRD-G-002 | [Architecture](../ARCHITECTURE.md)         | **Direct:** [semantic-map provenance](../../tests/test_record_semantic_map_provenance.py)                                                  |

## Corpus management requirements

| ID              | Requirement                                                                                                                                                                  | Acceptance criteria                                                                                                                                                                   | Parent               | Implementation trace                                               | Verification                                                                                                                                                                                                                     |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- | ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **PRD-COR-001** | Corpus-management workflows MUST preserve the distinction among source corpus state, published Record state, browser-loaded workspace state, and derived vector/index state. | UI labels and operations do not imply that clearing/rebuilding a derived store deletes the authoritative corpus or that browser-loaded JSONL is automatically canonical server state. | PRD-G-003, PRD-G-031 | [Architecture](../ARCHITECTURE.md); [User Guide](../USER_GUIDE.md) | **Architectural/Partial:** [semantic-map provenance](../../tests/test_record_semantic_map_provenance.py); [system metadata exemplars](../../tests/test_system_metadata_exemplars.py)                                             |
| **PRD-COR-002** | Import/merge/subset operations MUST preserve Record identities unless the operation deliberately creates new scholarly objects.                                              | Sorting, filtering, subset export/import, and merge do not silently mint new IDs for unchanged Records.                                                                               | PRD-G-009, PRD-G-017 | [User Guide](../USER_GUIDE.md)                                     | **Partial:** Records/workspace regression tests                                                                                                                                                                                  |
| **PRD-COR-003** | Corpus-level derived semantic graphs/maps MUST identify themselves as derived views rather than authoritative scholarly assertions.                                          | Graph nodes/edges may project reviewed metadata or NLP-derived relations but do not become independent authority merely by visualization.                                             | PRD-G-003, PRD-G-040 | [Architecture](../ARCHITECTURE.md)                                 | **Direct/Partial:** [semantic content graph](../../tests/test_semantic_content_graph.py); [record semantic map](../../tests/test_record_semantic_map.py); [semantic map frontend](../../web/tests/frontend/semantic-map.test.ts) |
| **PRD-COR-004** | Semantic map text segmentation/rendering MUST conserve the underlying text.                                                                                                  | Overlay/mention segmentation recombines to the original Record text and does not modify source content to support visualization.                                                      | PRD-G-009            | implementation contract                                            | **Direct:** [semantic-map domain](../../web/tests/frontend/semantic-map-domain.test.ts)                                                                                                                                          |
| **PRD-COR-005** | Derived corpus views that can expose reviewer-visible metadata MUST obey the same response filtering/authorization rules as ordinary Record reads.                           | Pending blind/second-opinion values or otherwise restricted values do not leak through semantic graph/map routes.                                                                     | PRD-G-018            | security/response-filter contract                                  | **Direct:** [second-opinion scrub](../../tests/test_second_opinion_scrub.py)                                                                                                                                                     |
| **PRD-COR-006** | Large semantic/corpus visualizations MUST remain bounded and usable rather than attempting to render unbounded graph state synchronously.                                    | Server/UI applies documented reduction, clustering, paging, level-of-detail, or equivalent strategies for large graphs.                                                               | PRD-G-033, PRD-G-028 | product performance contract                                       | **Partial:** [semantic graph panel](../../web/tests/frontend/corpus-semantic-graph-panel.test.ts); [packet reduction](../../tests/test_packet_reduction.py)                                                                      |
