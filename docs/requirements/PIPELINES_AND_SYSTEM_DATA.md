# Configurable Pipelines, Benchmarks, and System Data Requirements

**Scope:** Pipeline definitions, stage/strategy contracts, fallbacks, assignments, traces, dry-run comparison, fixed benchmarks, operational health, and System Data presentation.  
**Parent requirements:** [Global requirements](GLOBAL_REQUIREMENTS.md)

## Pipeline requirements

| ID | Requirement | Acceptance criteria | Parent | Implementation trace | Verification |
| --- | --- | --- | --- | --- | --- |
| **PRD-PIPE-001** | Executable pipelines MUST have explicit purpose, immutable identity/version, and a reproducible content hash. | A resolved execution can identify the exact `pipeline_id`, version, and hash used. Editing creates a new version rather than mutating historical execution identity. | PRD-G-010, PRD-G-014 | [Architecture](../ARCHITECTURE.md) | **Direct:** [pipeline contracts](../../tests/test_pipeline_contracts.py); [pipeline tracing](../../tests/test_pipeline_tracing.py) |

| **PRD-PIPE-003** | Pipeline parameters MAY tune computation but MUST NOT disable non-negotiable scholarly authority/provenance invariants. | Custom research/evidence/memory pipelines cannot bypass mandatory support, provenance, owner, reviewer-validation, or evidence-status rules applicable to their purpose. | PRD-G-010, PRD-G-012, PRD-G-016 | [PR #277](https://github.com/ajschlosser/DerridAI/pull/277); [PR #279](https://github.com/ajschlosser/DerridAI/pull/279) | **Direct:** [pipeline contracts](../../tests/test_pipeline_contracts.py); [research pipeline plan](../../tests/test_research_pipeline_plan.py); [evidence pipeline](../../tests/test_evidence_pipeline.py) |

## Comparison and benchmark requirements

| ID | Requirement | Acceptance criteria | Parent | Implementation trace | Verification |
| --- | --- | --- | --- | --- | --- |
| **PRD-PIPE-009** | Pipeline A/B comparison MUST be non-persistent with respect to ordinary Research output/state unless explicitly invoked as a benchmark store. | Dry comparison executes retrieval/rerank/diversity/provenance/context behavior but creates no Research answer, Research job, claim/response memory, grade, corpus mutation, or ordinary trace side effect. | PRD-G-003, PRD-G-034 | [PR #281](https://github.com/ajschlosser/DerridAI/pull/281) | **Direct:** [pipeline benchmark](../../tests/test_pipeline_benchmark.py); Pipeline comparison backend tests |
| **PRD-PIPE-010** | Fixed benchmark cases MUST be immutable/versioned and bind the question, instructions, retrieval controls, source collection, and relevant corpus/index fingerprint. | Material changes require a new case version; execution rejects corpus/index drift rather than pretending results are comparable. | PRD-G-014, PRD-G-034 | [PR #286](https://github.com/ajschlosser/DerridAI/pull/286) | **Direct:** [pipeline benchmark](../../tests/test_pipeline_benchmark.py); [benchmark panel](../../web/tests/frontend/pipeline-benchmark-panel.test.ts) |
| **PRD-PIPE-011** | Benchmarks MUST retain the exact compared pipeline definitions/hashes and relevant model/reranker identity. | A stored benchmark result identifies both pipelines and reproducibility metadata needed to interpret the run. | PRD-G-014, PRD-G-034 | [PR #286](https://github.com/ajschlosser/DerridAI/pull/286) | **Direct:** [pipeline benchmark](../../tests/test_pipeline_benchmark.py) (`test_benchmark_run_captures_exact_pipeline_and_reranker_identity`) |
| **PRD-PIPE-012** | Benchmark UI MUST present descriptive measurements without declaring a scholarly-quality winner. | Overlap, rank movement, candidate flow, timing, context size, and score distributions may be shown; the application does not collapse them into an unexplained overall winner. | PRD-G-034 | [PR #281](https://github.com/ajschlosser/DerridAI/pull/281); [PR #286](https://github.com/ajschlosser/DerridAI/pull/286) | **Direct/Partial:** [benchmark panel](../../web/tests/frontend/pipeline-benchmark-panel.test.ts); [System Data pipelines](../../web/tests/frontend/system-data-pipelines.test.ts) |
| **PRD-PIPE-013** | Benchmark cases/runs MUST participate in validated backup/restore with referential integrity. | Restored runs cannot reference unknown benchmark cases; case immutability and run bindings survive restore. | PRD-G-032 | [PR #286](https://github.com/ajschlosser/DerridAI/pull/286) | **Direct:** [pipeline benchmark](../../tests/test_pipeline_benchmark.py) (`test_pipeline_store_persists_cases_runs_and_backup`) |

## System Data requirements

| ID | Requirement | Acceptance criteria | Parent | Implementation trace | Verification |
| --- | --- | --- | --- | --- | --- |
| **PRD-SYS-001** | System Data MUST distinguish canonical scholarly state from caches, derived exemplars, pipeline traces, operational telemetry, and vector-store state. | Administrative copy identifies the role/authority of each dataset instead of presenting all databases as equivalent truth stores. | PRD-G-003, PRD-G-031 | [Architecture](../ARCHITECTURE.md) | **Partial:** [System Data pipelines](../../web/tests/frontend/system-data-pipelines.test.ts); [legacy System Data baseline](../../web/tests/e2e/legacy-dom-baseline.spec.ts) |
| **PRD-SYS-002** | Pipeline operational health metrics MUST be presented as computational telemetry, not scholarly validity. | Failure incidence, fallback counts, average/p95 runtime, strategy execution, latency, and candidate-flow data are labeled operational; UI does not infer research truth from them. | PRD-G-003, PRD-G-034 | [PR #280](https://github.com/ajschlosser/DerridAI/pull/280) | **Direct:** [System Data pipelines](../../web/tests/frontend/system-data-pipelines.test.ts) |
| **PRD-SYS-003** | System Data workspaces SHOULD preserve safe search/filter/pagination state in canonical URLs. | Copied URLs restore shareable state for Saved Responses, Metadata Examples, and related workspaces while excluding command-console free text and secrets. | PRD-G-020 | [PR #284](https://github.com/ajschlosser/DerridAI/pull/284) | **Direct:** [System Data workspaces](../../web/tests/frontend/system-data-workspaces.test.ts) |
| **PRD-SYS-004** | Derived metadata examples MUST be identifiable as rebuildable examples learned from reviewed canonical decisions. | UI copy does not present examples as an independent corpus authority. | PRD-G-003, PRD-G-016 | [Metadata Memory](../METADATA_MEMORY.md) | **Partial:** [unified memory/provenance](../../tests/test_unified_memory_provenance.py); System Data frontend coverage |
| **PRD-SYS-005** | Administrative diagnostics SHOULD expose expert detail progressively rather than requiring raw JSON/commands as the only interface. | Plain-language labels/status/explanations are primary; raw IDs, JSON, and command/query interfaces remain available where useful for expert administration. | PRD-G-022, PRD-G-031, PRD-G-037 | [PR #280](https://github.com/ajschlosser/DerridAI/pull/280); [User Guide](../USER_GUIDE.md) | **Partial:** [System Data pipelines](../../web/tests/frontend/system-data-pipelines.test.ts) |
| **PRD-SYS-006** | Free-form system query/command consoles MUST remain outside shareable URL persistence and SHOULD validate/explain commands before execution where the contract allows deterministic validation. | Sensitive/transient command text is not serialized into route state; invalid commands fail before destructive execution where validation exists. | PRD-G-020, PRD-G-023, PRD-G-031 | [PR #284](https://github.com/ajschlosser/DerridAI/pull/284) | **Partial/Gap:** System Data workspace URL tests cover exclusion; dedicated command-validation coverage should be linked when finalized |
