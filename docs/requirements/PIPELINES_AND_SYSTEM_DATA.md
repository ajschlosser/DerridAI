# Configurable Pipelines, Benchmarks, and System Data Requirements

**Scope:** Pipeline definitions, stage/strategy contracts, fallbacks, assignments, traces, dry-run comparison, fixed benchmarks, operational health, and System Data presentation.  
**Parent requirements:** [Global requirements](GLOBAL_REQUIREMENTS.md)

| **PRD-PIPE-009** | Pipeline A/B comparison MUST be non-persistent with respect to ordinary Research output/state unless explicitly invoked as a benchmark store.                        | Dry comparison executes retrieval/rerank/diversity/provenance/context behavior but creates no Research answer, Research job, claim/response memory, grade, corpus mutation, or ordinary trace side effect. | PRD-G-003, PRD-G-034 | [PR #281](https://github.com/ajschlosser/DerridAI/pull/281)                                                              | **Direct:** [pipeline benchmark](../../tests/test_pipeline_benchmark.py); Pipeline comparison backend tests                                                                       |
| **PRD-PIPE-010** | Fixed benchmark cases MUST be immutable/versioned and bind the question, instructions, retrieval controls, source collection, and relevant corpus/index fingerprint. | Material changes require a new case version; execution rejects corpus/index drift rather than pretending results are comparable.                                                                           | PRD-G-014, PRD-G-034 | [PR #286](https://github.com/ajschlosser/DerridAI/pull/286)                                                              | **Direct:** [pipeline benchmark](../../tests/test_pipeline_benchmark.py); [benchmark panel](../../web/tests/frontend/pipeline-benchmark-panel.test.ts)                            |
| **PRD-PIPE-011** | Benchmarks MUST retain the exact compared pipeline definitions/hashes and relevant model/reranker identity.                                                          | A stored benchmark result identifies both pipelines and reproducibility metadata needed to interpret the run.                                                                                              | PRD-G-014, PRD-G-034 | [PR #286](https://github.com/ajschlosser/DerridAI/pull/286)                                                              | **Direct:** [pipeline benchmark](../../tests/test_pipeline_benchmark.py) (`test_benchmark_run_captures_exact_pipeline_and_reranker_identity`)                                     |
| **PRD-PIPE-012** | Benchmark UI MUST present descriptive measurements without declaring a scholarly-quality winner.                                                                     | Overlap, rank movement, candidate flow, timing, context size, and score distributions may be shown; the application does not collapse them into an unexplained overall winner.                             | PRD-G-034            | [PR #281](https://github.com/ajschlosser/DerridAI/pull/281); [PR #286](https://github.com/ajschlosser/DerridAI/pull/286) | **Direct/Partial:** [benchmark panel](../../web/tests/frontend/pipeline-benchmark-panel.test.ts); [System Data pipelines](../../web/tests/frontend/system-data-pipelines.test.ts) |
| **PRD-PIPE-013** | Benchmark cases/runs MUST participate in validated backup/restore with referential integrity.                                                                        | Restored runs cannot reference unknown benchmark cases; case immutability and run bindings survive restore.                                                                                                | PRD-G-032            | [PR #286](https://github.com/ajschlosser/DerridAI/pull/286)                                                              | **Direct:** [pipeline benchmark](../../tests/test_pipeline_benchmark.py) (`test_pipeline_store_persists_cases_runs_and_backup`)                                                   |
