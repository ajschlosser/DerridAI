## Research thread workspace requirements

- **PRD-RES-011:** Thread history MUST remain owner-scoped durable application state, independent of response-cache and process-local job retention. The UI MUST retain a turn shell when its job is unavailable. **Partial implementation:** `research_thread_store.py`, `ResearchThreadBrowser.vue`; verified by `test_research_thread_store.py`, `test_research_thread_api.py`, and `research-threads.test.ts`.
- **PRD-RES-012:** Switching thread or owner MUST clear the previous thread's answer/evidence and reject late responses. Transient same-thread read failures SHOULD retain visible context with explicit retry. **Direct shell verification:** `research-threads.test.ts`, `research-progressive-loading.test.ts`, `research-threads.spec.ts`.
- **PRD-RES-013:** Follow-up questions MUST preserve original wording and use server-selected advisory context distinct from the current EvidencePacket. Prior generated answers MUST NOT become evidence through context inclusion. Each answer MUST retain an independent ResearchRun. **Planned context implementation:** Phases E–G of `RESEARCH_THREADS_IMPLEMENTATION_PLAN.md`; the current UI blocks follow-up submission. Applies existing cELF evidence/claim-binding and reproducibility invariants; no new conformance claim is made.

- **PRD-RES-014:** Thread management MUST use owner-scoped sparse mutations. Rename titles MUST apply the existing researcher text policy before mutation. Archive/unarchive MUST remain reversible and distinguishable in navigation. Deletion MUST require explicit confirmation, clear the selected workspace, and preserve the existing distinction between thread history, saved-response retention, and canonical provenance. Duplicate submissions and late mutation responses MUST NOT corrupt another thread/account workspace. **Direct verification:** `test_research_thread_api.py`, `test_research_thread_store.py`, `research-threads.test.ts`, and the keyboard/axe management workflow in `research-threads.spec.ts`.

- **PRD-RES-015:** New Research submissions MUST preserve server-created thread/run linkage. Inline answers and citations MUST remain associated with their originating turn and clear when access is revoked. Missing jobs MUST leave durable questions/status inspectable. Historical answers MUST NOT become corpus evidence through presentation. **Direct verification:** `research-workspace.test.ts`, `research-progressive-loading.test.ts`, `research-threads.test.ts`, and `research-threads.spec.ts`.

- **PRD-RES-016:** Failed/cancelled turns MUST support explicit in-place retry without duplicating the visible question. Retry MUST preserve the original question/instructions, disclose the use of current settings and selected evidence, retain normal run validation and authorization, prevent duplicate UI submissions, and refresh authoritative state after uncertain errors without automatically repeating mutations. Late submissions MUST NOT replace another route/account's selected result. Keyboard focus MUST reach the new attempt after hydration. **Direct verification:** `test_research_thread_api.py`, `test_research_thread_store.py`, `research-workspace.test.ts`, `research-progressive-loading.test.ts`, `research-threads.test.ts`, and `research-threads.spec.ts`.
