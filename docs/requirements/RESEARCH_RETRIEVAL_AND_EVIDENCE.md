# Search, Retrieval, Evidence, and Research Requirements

**Scope:** Search, hybrid retrieval, reranking/diversity, evidence acquisition, citations, Research generation, generated claims, support bindings, grading, and advisory memory use.  
**Parent requirements:** [Global requirements](GLOBAL_REQUIREMENTS.md)

## Search and retrieval requirements

| ID | Requirement | Acceptance criteria | Parent | Implementation trace | Verification |
| --- | --- | --- | --- | --- | --- |
| **PRD-SRCH-001** | Search MUST preserve the distinction between lexical, semantic, hybrid, filtered, and other retrieval mechanisms. | UI/trace state can explain which retrieval route(s) contributed to a result; vector similarity is not presented as the definition of retrieval itself. | PRD-G-003, PRD-G-037 | [cELF retrieval terminology](../../SPECIFICATION.md) | **Partial:** retrieval/pipeline tests; [pipeline tracing](../../tests/test_pipeline_tracing.py) |
| **PRD-SRCH-002** | Retrieval diagnostics MUST remain run/candidate state rather than being persisted as authoritative source-record metadata. | Rank, route, RRF, similarity, rerank score, and selection state remain bounded trace/result attributes. | PRD-G-003 | [cELF durable vs derived state](../../SPECIFICATION.md) | **Direct/Partial:** [pipeline tracing](../../tests/test_pipeline_tracing.py); [pipeline benchmark](../../tests/test_pipeline_benchmark.py) |
| **PRD-SRCH-003** | Search workspaces SHOULD preserve safe shareable query/filter/sort/column/page state in canonical URLs. | Copying or navigating back to a Search URL restores the shareable workspace state without serializing local source data or secrets into the URL. | PRD-G-020 | [PR #270](https://github.com/ajschlosser/DerridAI/pull/270) | **Direct:** [Search workspace](../../web/tests/frontend/search-workspace.test.ts) |
| **PRD-SRCH-004** | Retrieval fallback MUST be explicit and traceable. | Unavailable/timeout/error fallback records the fallback kind/reason and target strategy rather than silently changing retrieval behavior. | PRD-G-010, PRD-G-025 | [PR #277](https://github.com/ajschlosser/DerridAI/pull/277); [PR #278](https://github.com/ajschlosser/DerridAI/pull/278) | **Direct:** [progressive metadata retrieval](../../tests/test_progressive_metadata_retrieval.py); [metadata-precedent pipeline](../../tests/test_metadata_precedent_pipeline.py) |
| **PRD-SRCH-005** | Language routing MUST normalize regional source-language variants to supported retrieval-language identities without rewriting the source's bibliographic language metadata. | Regional English variants route to `en`; French variants route to `fr`; source metadata remains independently representable. | PRD-G-008, PRD-G-027 | [User Guide](../USER_GUIDE.md) | **Direct/Partial:** [language identity](../../tests/test_language_identity.py); [source language fallback](../../tests/test_source_language_fallback.py) |
| **PRD-SRCH-006** | Search filters over scholarly metadata SHOULD derive available fields from the relevant metadata schema rather than a global hard-coded field list. | Advanced search condition builders expose fields applicable to the selected corpus/schema. | PRD-G-007, PRD-G-021 | [User Guide](../USER_GUIDE.md) | **Partial:** [Search workspace](../../web/tests/frontend/search-workspace.test.ts); metadata-schema frontend tests |
| **PRD-SRCH-007** | Retrieval candidate lineage SHOULD be retained in bounded form where needed for audit/comparison without copying unnecessary source text into telemetry. | Pre-rerank, post-rerank, and selected candidate IDs/ranks/routes/scores can be inspected; diagnostic traces avoid duplicating full source content. | PRD-G-002, PRD-G-010, PRD-G-014 | [PR #281](https://github.com/ajschlosser/DerridAI/pull/281) | **Direct:** [pipeline benchmark](../../tests/test_pipeline_benchmark.py); [pipeline tracing](../../tests/test_pipeline_tracing.py) |

## Evidence requirements

| ID | Requirement | Acceptance criteria | Parent | Implementation trace | Verification |
| --- | --- | --- | --- | --- | --- |
| **PRD-EVD-001** | Relevance ranking alone MUST NOT make a candidate valid reviewer evidence. | Candidate evidence must pass the configured direct-support and provenance gates before selection as reviewer-authoritative evidence. | PRD-G-012 | [PR #279](https://github.com/ajschlosser/DerridAI/pull/279) | **Direct:** [evidence pipeline](../../tests/test_evidence_pipeline.py) |
| **PRD-EVD-002** | Provenance validation MUST verify that evidence resolves to a real source unit/document in the current source context. | Missing source-document/source-unit identity is rejected rather than silently accepted. | PRD-G-002, PRD-G-012 | [PR #279](https://github.com/ajschlosser/DerridAI/pull/279) | **Direct:** [evidence pipeline](../../tests/test_evidence_pipeline.py) (`test_provenance_gate_rejects_candidates_without_source_document_identity`) |
| **PRD-EVD-003** | Required evidence gates MUST also apply to fallback strategies. | A fallback CrossEncoder/LLM/lexical candidate cannot bypass support/provenance validation merely because the primary strategy failed. | PRD-G-012, PRD-G-033 | [PR #279](https://github.com/ajschlosser/DerridAI/pull/279) | **Direct:** [evidence pipeline](../../tests/test_evidence_pipeline.py); [pipeline contracts](../../tests/test_pipeline_contracts.py) |
| **PRD-EVD-004** | Evidence references MUST preserve resolvable Record/SourceSpan identity independently of rendered citation text. | An `EvidenceRef` can be followed back to the current Record revision and source location. | PRD-G-002, PRD-G-013 | [cELF EvidenceRef](../../SPECIFICATION.md) | **Direct:** [research object graph](../../tests/test_research_object_graph.py); [traceability explorer](../../web/tests/frontend/record-traceability-explorer.test.ts) |
| **PRD-EVD-005** | Citation generation MUST reflect actual source locators and MUST NOT invent unsupported precision. | Audio uses time ranges/speaker labels; physical PDF page and printed page remain distinguishable; missing locator precision is not fabricated. | PRD-G-008, PRD-NFR-011 | [cELF Citation](../../SPECIFICATION.md) | **Direct/Partial:** [research object graph](../../tests/test_research_object_graph.py); [document layout](../../tests/test_document_layout.py) |
| **PRD-EVD-006** | Evidence/support state MUST become stale when the underlying material changes such that the original binding is no longer current. | Revision-aware support/citation state can distinguish current vs stale evidence instead of silently carrying old bindings forward. | PRD-G-009, PRD-G-013 | [cELF SupportBinding](../../SPECIFICATION.md) | **Partial:** [corpus precedents](../../web/tests/frontend/corpus-precedents.test.ts); [review decisions](../../tests/test_review_decisions.py) |

## Research requirements

| ID | Requirement | Acceptance criteria | Parent | Implementation trace | Verification |
| --- | --- | --- | --- | --- | --- |
| **PRD-RES-001** | Research generation MUST operate over an explicit evidence/context packet rather than treating the entire corpus or retrieval cache as implicit authority. | The run records supplied evidence/context and generated output can be audited against it. | PRD-G-001, PRD-G-013 | [cELF EvidencePacket/GenerationRun](../../SPECIFICATION.md) | **Direct/Partial:** [pipeline tracing](../../tests/test_pipeline_tracing.py); [unified memory/provenance](../../tests/test_unified_memory_provenance.py) |
| **PRD-RES-002** | Generated claims SHOULD be materialized with stable claim identity and explicit SupportBindings where the workflow claims grounded research. | Claim objects and support bindings can be queried independently of rendered answer text and citations. | PRD-G-013 | [cELF GeneratedClaim/SupportBinding](../../SPECIFICATION.md) | **Direct:** [research object graph](../../tests/test_research_object_graph.py); [unified memory/provenance](../../tests/test_unified_memory_provenance.py) |
| **PRD-RES-003** | Research memory MUST remain advisory and subject to eligibility/owner/evidence rules. | Prior claim/response memory may guide a run but cannot silently satisfy current evidence requirements or cross owner boundaries. | PRD-G-016, PRD-G-018 | [PR #277](https://github.com/ajschlosser/DerridAI/pull/277) | **Direct:** [memory pipeline](../../tests/test_memory_pipeline.py); [claim memory](../../tests/test_claim_memory.py); [research memory](../../tests/test_research_memory.py) |
| **PRD-RES-004** | Research runs MUST retain the exact resolved pipeline identity and bounded execution trace needed to explain retrieval/context behavior. | Run detail can expose pipeline ID/version/hash and relevant stage observations without conflating telemetry with evidence authority. | PRD-G-010, PRD-G-014 | [PR #277](https://github.com/ajschlosser/DerridAI/pull/277) | **Direct:** [pipeline tracing](../../tests/test_pipeline_tracing.py) |
| **PRD-RES-005** | Research generation SHOULD support streaming and truthful cancellation semantics. | Closing/cancelling generation stops current model streaming where supported; retrieval/reranking stops at safe checkpoints; UI can represent `cancelling` while work winds down. | PRD-G-024 | [User Guide](../USER_GUIDE.md) | **Partial:** [operations panel](../../web/tests/e2e/operations-panel.spec.ts); job/realtime tests |
| **PRD-RES-006** | Research grading MUST remain a distinct evaluative operation and MUST NOT mutate source evidence or corpus authority. | Grades/analysis attach to research output/run state and do not rewrite Records or evidence. | PRD-G-003, PRD-G-034 | [User Guide](../USER_GUIDE.md) | **Partial:** RAG grading tests and pipeline contracts |
| **PRD-RES-007** | Research prompt construction MUST remain corpus-neutral while preserving runtime authorship/attribution context. | Built-in research/grading prompts may include `document_author` evidence/context but do not bake in Derrida or another named author as a universal assumption. | PRD-G-006, PRD-G-008 | [PR #268](https://github.com/ajschlosser/DerridAI/pull/268) | **Direct:** [prompt author neutrality](../../tests/test_prompt_author_neutrality.py) |
| **PRD-RES-008** | Researcher-visible citations and traceability views MUST provide a path from output back to supporting documentary objects. | Users can inspect claim/support/evidence/Record/source relationships without relying only on opaque retrieval scores. | PRD-G-013, PRD-G-037 | [cELF reverse audit paths](../../SPECIFICATION.md) | **Direct/Partial:** [traceability explorer](../../web/tests/frontend/record-traceability-explorer.test.ts); [research object graph](../../tests/test_research_object_graph.py) |
