# 0.62.14 — Tidy Tern

Fixes from a round of bug reports against the Corpus Builder.

- **Preparing the record workspace is a panel, not a takeover.** It sits on the page with its progress and a cancel button, and the page stays usable.
- **Save document structure is below the PDF**, where you finish, not above it.
- **A suggested first main-text page appears in the structure editor.** The inference from 0.62.10 only filled the document metadata at build time, so it never showed where you set the anchors. It now fills an empty "First main-text page" with its clues, for you to check and save, and assets uploaded earlier get it the first time they are read. It also recognises numbered headings ("1. Title", "I. Title") and the first bookmark after the front matter. A value is still offered only at 90% confidence or more, so a PDF with few clues still gets no suggestion.
- **A model you switch to mid-run is used** for the records not yet started and appears in the metrics table beside the first one. Requests already in flight finish on the old model.
- **Menus stay inside the window.** The action menu flips to the other edge or above when it would leave the screen.
- **The end of a long record is no longer clipped** by the warning and decision bar; the pane scrolls instead.
- **Bulk edit reads like Edit document metadata.** Both now share the same section, field and footer components. A field is changed by giving it a value; empty fields are left alone; "Clear on every record in scope" is the deliberate way to blank one. Document details (title, author, publisher…) moved to the end with a note that they are inherited from Edit document metadata.
- **LLM touch-up with a FreeLLM/OpenAI-compatible profile no longer fails with HTTP 422.** Such profiles allow 32 parallel requests; the request allowed 16 and rejected the rest. It is now clamped.
- **Stray prompt tags are trimmed from touch-up output** (`<SOURCE_TEXT/>` and similar): anything at the very start or end of the answer that is not at the start or end of the source was added by the model and is removed. Markup that belongs to the source is kept.
- **Placeholders are not values.** "null", "N/A", "unknown" and generic roles such as "the author of the current record" are dropped from model proposals and never appear in dropdowns; the prompt tells the model to return null instead.
- **The logo has a transparent background** (inverted to light ink on dark themes). The favicon and app icons keep their white background.
- **`web/node_modules` is no longer tracked.** A symlink to it was committed by mistake in 0.62.12; the ignore rule did not match a symlink.

## What is not done

- No transparent original of the logo existed in the repository or on this machine; the transparent files were generated from the opaque ones by removing the near-white paper colour. Replace them with your original if you have one (`web/public/brand/`).
- Placeholder values already stored on records are not rewritten; they are only hidden from dropdowns.
- The 422 fix is confirmed for the concurrency limit; I did not run touch-up against a live FreeLLM/OpenAI server.
- The "Preparing" panel and the save-structure position are covered by unit tests, not a browser check.
