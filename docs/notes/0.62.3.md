# 0.62.3 — Vigilant Viper

Vector Stores can talk to a running Chroma server the same way DerridAI talks to Ollama, and the workspace itself is a Vue page. Embedded local-filesystem Chroma remains the default. No data migration is needed; switching backends does not move collections.

- **Three backends, one writer:** `CHROMA_MODE=embedded` (default) keeps `PersistentClient` on `CHROMA_PATH`. `CHROMA_MODE=http` uses `HttpClient` against a server URL. The optional compose profile `chroma` is the bundled server (`./data/chroma-server`, published on host port 8001); a lab or host-run server uses `CHROMA_BASE_URL` the same way `OLLAMA_BASE_URL` does. Do not point embedded storage and a server at the same directory.
- **Probe then apply:** Vector Stores → Connection settings tests a backend without replacing the live client. Apply adopts it only after the probe succeeds. Tokens belong in the access-token field, never in the URL, health chip, logs, or backup identity. `HttpClient` is opened with hostname and port, not a full origin as `host`.
- **HTTP NUKE and backup:** NUKE against a server deletes that server's collections and does not empty a leftover local `./data/chroma`. Backups still go through the client API and record the backend mode and origin in the manifest.
- **Vue workspace:** `/databases` is a native Vector Stores page (header, collection rail, hero, overview/data/retrieval/builds/settings). Collection creation, upsert, and JSONL export still use the existing runtime wizard and refresh Vue through `derridai:vector-stores-changed`. Researchers are sent to Search with database scope; connection and collection mutation stay admin-only on the API.
