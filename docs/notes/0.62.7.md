# 0.62.7 — Nocturnal Newt

The Vue views now take their colours from the design tokens, so dark mode works in Languages, Response Library, Record, Settings and Compare as well as the Corpus Builder. These views had no Storybook stories and had never been scanned by axe, so they are now rendered in the real app against a mock API and checked in light and dark.

- **Dark mode in the views.** Against the real app, axe found 33 contrast failures in light mode and 92 in dark on the pages checked, mostly in Languages; it now finds none in either. Settings and Compare had 2 in dark, now none. Languages, Response Library and Record no longer contain a literal colour, and the shared provider card, the language header, the Corpus Builder page frame and the global stylesheet lost their translucent-white backgrounds, which turned into pale slabs on a dark surface.
- **Four defects the new coverage found.** The saved-answer heading on the Response Library and Research pages was declared at 112px, so a saved question filled the screen; it is now heading-sized. The provider card squeezed its name to nothing and let its stat boxes overlap the DEFAULT badge in a narrow column, such as the one on the Languages page, because it stacked by the width of the window instead of its own; it now stacks by the space it is given. Search highlights in the record text kept the theme's light text on a fixed yellow fill in dark mode (1.05:1); the highlighter is now a fixed pair, dark text on yellow. The record's find box had only a placeholder for a name; it is now labelled.
- **Migration tool.** `scripts/migrate-css-tokens.py` now also turns a translucent white background into a mix of `--card`, which is how most of the pale slabs were made. It is a dry run unless given `--apply`.
- **Guardrails.** A new end-to-end spec renders 15 view states (Languages with a policy warning, an install dialog, a translation report and a running job; the Response Library with and without saved answers and its archive dialog; Record with a search, tabs and no record; Settings; Compare) in light and in dark and scans each with axe, plus checks for the provider card layout and the heading size. The literal-colour ratchet now covers the views (zero) and rejects translucent-white backgrounds.
- **Running it.** The end-to-end run now also serves the production build on port 5199 (set `APP_PORT` to move it) with a mock API in `web/tests/e2e/support`, so run `npm run build` before `npm run test:e2e`.

## What is not done

- Four Storybook stories still fail axe in both schemes, none in the Corpus Builder or the views above: `compare-diff--identical`, `foundations-navigation-tabs--collection-sections`, `settings-search--empty` and `vector-stores-collection-rail--filtered-empty`. They are ARIA structure problems (a listbox without options, a tab whose panel does not exist), not colour, and they were already there.
- The Works page is drawn by the older runtime rather than a Vue view. Its styles are in the global stylesheet, which is migrated, but it is not among the states scanned.
- The scanned states are the ones listed above; loading states, error toasts, and dialogs not listed were not exercised. The mock API answers with plausible data, not a real backend.

## Validation

Linux, Python 3.12, Node 22, on the branch after merging `master` at 0.62.6:

- pytest, `ruff` and `mypy` passed. Vitest: 214 passed. `eslint`, `vue-tsc`, the production build and the Storybook build passed.
- Playwright with axe (WCAG 2.0 to 2.2, A and AA): 152 passed, 34 skipped by design (the view and story sweeps run once, at desktop width).
- An earlier form of the view spec (29 tests) failed 14 of them when run against the code from before this change, so it does detect what it was written for.
- Across all 261 Storybook stories, axe failures in light stay at the 4 above, and dark went from 9 stories to the same 4 (measured in two steps: the whole Storybook showed 6, then the two record reading-pane stories were fixed and re-checked); no story fails that passed before. Light mode was compared pixel by pixel against the previous version: 10 stories differ, and every difference is accounted for (the heading fix, and text that changes between runs such as a timestamp and a port number).
