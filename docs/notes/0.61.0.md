# 0.61.0 — Undulating Umbrellabird

A maintainability and safety release. The corpus-build pipeline is decomposed into explicit stages, static analysis becomes a CI gate, correctness-affecting fallbacks now surface instead of hiding, and authentication gains a Secure-cookie option and a failed-login throttle.

- **RAG:** researcher submissions use the approved server provider profile's model.
- **CI:** separate Ruff, mypy, and ESLint jobs with justified, tracked suppressions (`docs/STATIC_ANALYSIS_FOLLOWUPS.md`).
- **Corpus builder:** metadata rules extracted to `corpus_metadata.py`; metadata enrichment split into source-quality gating, task preparation, execution, and reconciliation; build orchestration split into scope preparation, topology construction, enrichment scheduling, and finalization (`corpus_pipeline.py`); publication validation and serialization extracted to `corpus_publication.py`. Existing names remain as compatibility delegates.
- **Frontend:** corpus lifecycle computed state and authoritative review-domain rules moved into `web/src/domain` with unit tests.
- **Failure visibility:** PDF page-label lookup failures, build-state refresh failures, unreadable live reviewer ownership, editorial-memory failures, response-cache storage failures (distinct from an absent cache), keyword-search storage failures, and job checkpoint/status-sync failures are now surfaced as build warnings, failed stage/field statuses, or propagated errors. Remaining swallowed exceptions are commented with why they are safe.
- **Authentication:** `SESSION_COOKIE_SECURE` (default `false`; set `true` behind an HTTPS reverse proxy). Failed logins are throttled per normalized username in the existing auth SQLite database (`AUTH_LOGIN_MAX_FAILURES`, default 5; `AUTH_LOGIN_LOCKOUT_SECONDS`, default 300). Unknown usernames spend the same password-hash work and are throttled identically, so responses do not reveal whether an account exists.
- **Docs:** `CHANGELOG.md`, `CONTRIBUTING.md`, and `docs/ARCHITECTURE.md` added.

Not in this release: splitting `main.py` into routers and `chroma_store.py` into search/cache/sync modules (documented follow-ups).
