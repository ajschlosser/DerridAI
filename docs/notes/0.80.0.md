# 0.80.0 — Beverly

This release advances DerridAI from the 0.70.0 Amesbury baseline through the
metadata, provenance, corpus-builder, frontend, and validation work completed
on the way to the canonical assertion migration. The release keeps the
existing JSONL and review contracts usable while making provenance and
evidence state durable enough to survive schema, model, and retrieval changes.

## Corpus Builder and source ingestion

- Continued the decomposition of the legacy runtime and `PdfCorpusBuildManager`
  into focused Vue domain modules and backend mixins, including build lifecycle,
  manifest workflow, segmentation, enrichment execution, review actions,
  operations, editorial memory, schema/profile resolution, and reviewer
  transport helpers.
- Added generic source-media ingestion for text, Word documents, images, audio,
  URLs, and Project Gutenberg sources while retaining source spans and
  deterministic metadata checks.
- Improved corpus metadata schemas, document-structure review, enrichment
  reruns, source-quality handling, record-quality validation, and publication
  readiness without making model output authoritative by default.

## Metadata, provenance, and review

- Added the canonical `FieldAssertion` model with independent derivation,
  evaluation, authority, value-state, confidence, evidence, revision, and
  stable field-identity semantics.
- Added lazy, idempotent migration from top-level metadata values,
  `metadata_field_status`, and `metadata_evidence` into canonical assertions.
  Legacy fields remain compatibility projections, while deterministic,
  model-inferred, human-confirmed, overridden, unresolved, invalid, and
  confirmed-absent states remain distinguishable.
- Preserved legacy audit markers and status vocabulary during migration,
  including blind-review, recheck, raw model-value, confidence, and
  `llm_checked` metadata. Human authority transitions clear stale legacy
  projections rather than silently retaining them.
- Integrated canonical assertions into repository load/save and pagination,
  deterministic metadata constraints, enrichment reconciliation, autonomous
  settlement, review-state derivation, publication, provenance memory, and
  evidence binding.
- Kept blind and second-opinion reviewers from receiving sealed values,
  canonical assertion identifiers, model reasoning, or hidden evidence while
  retaining the internal audit trail needed to score the review.
- Added stable semantic compatibility identifiers for built-in fields and
  schema-defined identities for custom fields. Custom metadata now travels
  through touch-up and RAG payloads and appears in dynamic search facets.
- Preserved the evidence-bound metadata memory and reviewed-evidence behavior
  introduced during the 0.70.x development cycle.

## Research, retrieval, and application surfaces

- Continued native Vue migration across Records, Search, Compare, Works,
  Vector Stores, Settings, Dashboard, PDF Explorer, and Response Library
  surfaces, removing obsolete runtime hosts where the replacement was complete.
- Added or refined search filters, provider configuration, language handling,
  annotations, system-data inspection, and researcher-facing record views.
- Kept retrieval, vector storage, response caching, and generated research
  output separate from authoritative corpus records and source provenance.

## Reliability and engineering

- Added API route contracts, typed frontend test projects, focused backend
  regression taxonomy, parallel CI configuration, scoped frontend quality
  gates, and improved Playwright synchronization.
- Extracted job-manager responsibilities and removed obsolete compatibility
  exports and dead paths where the replacement modules made them unnecessary.
- Maintained English/French locale parity, accessibility and design-token
  checks, backup/restore coverage, authentication boundaries, and researcher
  access restrictions while changing the record model.

## Validation

- Backend targeted migration, review, publication, status-vocabulary, and
  reviewer-transport tests: **54 passed**.
- Full serial backend suite in the Docker test environment: **567 passed**.
- Frontend typecheck, unit tests, production build, Storybook build, and
  Playwright/axe suites were not rerun for this release because the worktree
  does not contain `web/node_modules`.
- Docker image builds and frontend dependency installation were not claimed as
  release validation beyond the containerized backend test run above.
