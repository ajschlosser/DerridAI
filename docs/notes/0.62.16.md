# 0.62.16 — Discreet Dormouse

- **The enrichment "highlighted changes" now exist.** After a pass changes a record it is reopened with "Metadata enrichment added, replaced, or disputed metadata; review the highlighted changes.", but nothing highlighted them: the record kept the details (`metadata_enrichment_history`) and the interface never showed them. The Metadata tab now opens with "Changed by the last enrichment pass": values added, values replaced (old value struck through, with "Restore previous"), and disagreements where the pass left the current value and proposed another (with "Keep current" and "Use proposed"). A change drops off the list once you decide that field. It uses the theme tokens; axe finds no violations in light or dark.
- **A second reviewer's blind answer is hidden in every response.** In 0.62.13 a second reviewer could not see the first reviewer's answer in the record list or after saving metadata, but other responses that carry a record (accept, disposition, merge, split, touch-up, bulk edit…) could still include it. Every corpus-build JSON response now passes through one filter that blanks, for the reviewer who owes a second opinion, the answer, its status, its decision-log entry and its evidence. It runs only when a response mentions a second opinion, and only for that reviewer. Checked through the running app for the accept route.
- **The provider model list is tested in light and dark mode**, with axe, in the browser against the mock API.

## What is not done

- The filter covers `/api/pdf/corpus-builds` responses. A record reached through another route (for example a published store) is not a second-opinion record and is not affected.
- There is still no queue view of pending second opinions, only the API, and second reviewers must be administrators.
- Blinding is checked for the accept route through the running app and for the others by the shared filter's unit tests, not route by route.
