# 0.82.0 — Gloucester

Gloucester is the first consolidated release after **0.81.0 — Fall River**. It turns the broad post-Fall-River feature set into a more progressive, concurrent, portable, and inspectable research environment without weakening DerridAI's distinction between authoritative scholarly state and derived computation.

The release baseline is annotated tag v0.81.0 at 91f12974cef29bdc2c60fac4aef1960bb0c26b5b. The Gloucester release branch starts from master at b55a65c223166f0080c33ea2b5baa3b38ed14a68 after PRs #493 and #494. The release tag is v0.82.0, annotated with **0.82.0 - Gloucester**.

## Release identity

- The application version is **0.82.0** with codename **Gloucester**.
- Browser/API build labels combine version, codename, and the git commit when a commit is available.
- The browser title, backend version constant, package metadata, package lock, multilingual README family, release notes, changelog, and legacy build-info baselines move together in this release.
- The sign-in screen continues to expose build identity; authenticated commit visibility remains role-appropriate.

## General direction

Gloucester is less a single-feature release than a consolidation cycle:

- Corpus Builder becomes a progressive **Setup → Build → Review → Publish** workflow that can hand useful Records to reviewers while automation continues.
- Metadata and evidence processing performs less unnecessary model work while making support, authority, and no-value semantics stricter.
- Pipeline Studio increasingly describes computation DerridAI actually executes, with typed inputs, resolved wiring, scholarly effects, traces, latency, complexity, and comparison.
- Static publication becomes a portable research environment with a public TypeScript SDK, local semantic indexing, reader-configured providers, deterministic citations, multiple delivery modes, and a Vue reference interface.
- Realtime invalidation and progressive loading replace broad polling, blank-page refreshes, and manual Refresh controls on more surfaces.
- Large-corpus work is increasingly Record-local, revision-aware, bounded, and coordinated so background processing interferes less with human review.
- cELF is clarified as a product-neutral lexical/documentary information model rather than a retrieval-centric architecture.
- The frontend continues to retire its legacy runtime in favor of Vue, router-owned navigation, typed shared state, and focused domain modules.

## Corpus Builder

### Progressive Setup → Build → Review → Publish

Corpus Builder now presents four explicit workflow workspaces with clearer ownership. Setup configures the build, Build represents active execution, Review handles scholarly decisions, and Publish answers whether the corpus is ready and what remains to fix. Redundant lifecycle rails and overlapping status panels were consolidated. (#326, #336)

Setup now exposes numbered required steps, strict completion separately from warnings, visible state labels, readable collapsed summaries, and one canonical Build Plan/preflight surface. Advanced settings remain visibly optional, record sizing is grouped with Structure where appropriate, and warnings/capacity notes appear inline instead of in a duplicate setup-review popover. (#402)

Pre-build document metadata is shown as a compact summary of work identity, publication/language/translator information, provenance/detected values, reviewer edits, and required-field state. The complete editor opens only on request, and document-level defaults are explicitly separated from the Record metadata schema. (#413)

The SourceUnit preview samples from roughly 20% into the included units when enough material exists, reducing front-matter-biased previews. Audio Setup reports known duration when available. (#398, #329)

### Review while automation continues

As soon as Records are usable, Review can become the primary next action while enrichment continues. Build distinguishes **Preparing**, **Enriching**, **Ready for review**, and **Needs attention** instead of treating all unfinished work as one state. Activity history and technical detail live under **Run details** so current state and next action remain dominant. (#404)

Multiple Records can enrich concurrently. Active task identities are grouped by Record, filtered queue selection remains valid as Records move between queues, unsaved drafts are protected from background selection changes, and pagination recovers when concurrent queue shrinkage empties the current page. (#407, #410)

Provider capacity is coordinated process-wide across Corpus Builder, Research/RAG, LLM jobs, and LLM tools. Corpus Builder supports the provider contract's full concurrency range of 1–64 instead of the former hidden 16-request ceiling while still respecting the shared provider limit. Metadata families, segmentation classifiers, and second-reader work use bounded concurrency with deterministic application. Live provider active/limit information is visible in Corpus Builder. (#408, #410)

### Explicit SourceUnit → Record → Page topology

Build creation now persists a topology policy. Semantic segmentation remains the default, while fixed SourceUnit grouping can deterministically produce one Record from one or more SourceUnits without later refinement silently changing that relationship. Sources without authoritative pagination can optionally group Records into synthetic Pages; physical/detected pagination remains authoritative. The relationship is visible in Setup and the Build Plan. (#407, #410)

Text, HTML, Word, and RTF sources can receive page numbers from Gutenberg/Wikisource structure, Word/RTF page breaks, or printed-page patterns. Wikisource imports can retain bounded DjVu scan images. When no printed pages are found, DerridAI can estimate pages at about 300 words and offer one-Record-per-page behavior. Audio remains time-based. (#400)

PDF reviewers can define repeating layout regions such as facing-page columns, margin columns, inset boxes, quotation bands, or running regions and apply them to every page, odd/even pages, ranges, or a single page. Separate regions remain separate reading threads while keeping page provenance. (#361)

### Review hierarchy and editing

The current Record is easier to identify: sequence/page locator leads, while citation and raw Record ID become secondary context. Metadata that still requires a decision is explicitly marked **Needs review** and remains in its actual editable control; settled or auto-resolved fields collapse to a compact value row with Edit. (#397)

Unreviewed model suggestions open directly in their editor. Model output that merely echoes the field name is rejected as a value while its raw output remains auditable. (#394)

The Review queue is denser and clearer: one accepted/remaining progress measure replaces competing counts, sequence/page leads rows, more Records fit on screen, the text pane receives more space, evidence actions are real buttons, and focus/medium-width behavior is improved. (#388)

Opening a Record no longer writes canonical activity merely for navigation. Hidden precedent/autocomplete assistance is deferred until Metadata is actually visible, reducing cache churn and review latency. (#455)

### Publication readiness and focused remediation

Publish readiness is the authoritative top-level decision state. The Publish workspace shows one primary next action and turns blockers into the remediation worklist; supporting metrics move to Review details. (#399)

**Continue review** starts a bounded remediation session on the first actionable blocker, preserving the exact Record, field, source-quality issue, boundary problem, or validation finding. Resolving an item advances to the next relevant blocker and automatically returns to Publish when blockers reach zero. (#403)

Autonomous/unreviewed publication no longer rewrites epistemic state to make a Record look reviewed. FieldAssertion derivation, evaluation, authority, value state, confidence, evidence, and failure provenance are preserved, while publication records human/autonomous/hybrid decision counts. cELF Core/Publication conformance is evaluated independently of review mode. (#316)

The former “Accept all suggestions and publish” wording was replaced with explicit unreviewed-publication language and a focused decision dialog that explains remaining review scope and the authority implications. (#319)

### Resume, early text review, audio, and repeatable metadata

Interrupted builds resume through a strict execution-override envelope; checkpoints and human review survive, orphaned operations are normalized after restart, and startup does not silently replay work. (#417)

After current topology is validated and durably stored, text-only review can begin before every preparation stage is complete. Metadata, structural changes, and disposition remain gated. On resume, canonical source coverage and current Record text are revalidated before early text review is re-enabled. Save-response reuse is allowed only when both RecordRevision and the operational queue version still match. (#464, #472)

Diarized audio voices are normalized to stable speaker identities such as SPEAKER_1 while provider labels remain extraction provenance. Researchers can review/edit speaker assignments before or during builds, and assignments project into current/future Records. (#427)

Metadata schema format 3 adds bounded repeatable associated groups with stable group/instance identity and Record- or corpus-scoped values, allowing numbered presentation without dynamic numbered field keys. (#427)

Audio manifests/validation no longer assume page locators. Timed units validate by time range, paged units retain page checks, and malformed locator states are reported. Sources tables refresh correctly after capture completion, partial completion, failure, cancellation/interruption, dialog close, and bulk deletion while retaining page/filter state. (#401)

## Metadata, evidence, and scholarly authority

### Cardinality and semantic identity

Metadata schema type is now authoritative for scalar versus list editing. Historical one-item scalar arrays can be unwrapped losslessly; ambiguous multi-item scalar arrays require explicit reviewer resolution rather than silent merge/drop. Metadata Memory examples are normalized to the active schema before reuse. (#317)

A deterministic semantic-identity layer classifies values as exact, equivalent, different, or unknown under field policy without requiring a model call. Equivalent values can be accepted without pretending their evidence became human-produced; different values remain corrections; unknown relationships remain unresolved rather than contaminating acceptance/calibration counts. (#321)

Researchers can maintain reviewed aliases/distinctions for people, works, and concepts. Identity changes retain history and can be copied from another corpus with conflict reporting. Semantic maps use reviewed identities instead of blindly merging similar names. (#321)

### NLP remains advisory

POS, NER, and Document Intelligence output are treated as field-local advisory cues rather than scholarly metadata or source evidence. Raw tag lists no longer leak into metadata value/evidence fields, stop-word-only candidates are suppressed, and boolean false is treated as a substantive supported value rather than absence. (#340, #363)

Build and Record Review surfaces expose actual linguistic-analysis provenance such as spaCy version/model/language/status/coverage. (#340)

### Deterministic-first model routing

Automatic enrichment performs less model work where deterministic or reviewed information already resolves a field. Strong reviewed-memory values can remove only resolved fields from a family request; quotation generation can be skipped for ordinary prose; indexing generation can be skipped when reviewed memory resolves all indexing fields; and precedent retrieval is scoped to families actually scheduled. (#366, #369)

Exact current-text NER spans can become unreviewed candidate assertions only for stable direct-mention indexing semantics such as named people/referenced works. Interpretive fields remain model/reviewer tasks. Explicit human reruns retain the full requested contract. (#369)

### Structured completion repair/retry

DerridAI now uses a shared structured-completion policy that strict-parses first, locally repairs malformed-but-complete JSON where safe, distinguishes malformed/schema-invalid/truncated/timeout/transport failures, does not “repair” structurally incomplete token-limited output, and uses failure-specific retry prompts/output budgets. Provider finish reasons are preserved. (#374, #380)

### No-value state and optimistic review

A model proposal that no supported value exists no longer inserts placeholder prose such as “[not established in source]” into scholarly metadata. The field remains empty and the proposal is represented as cELF no-value state. Legacy placeholder strings remain readable but are filtered as values. (#385)

Metadata decisions optimistically update review projections so the reviewer can advance without waiting for persistence; authoritative serialized writes later reconcile that state. (#385)

Evidence confidence is no longer displayed/retained when no valid source span is actually bound. (#385)

### Evidence recovery cascade v2

Automatic recovery now defaults to **evidence.recovery.cascade@2**. Direct support exits early; semantic retrieval, CrossEncoder reranking, and MMR may rank a bounded shortlist; but relevance scores cannot establish evidence. Only deterministic support validation or an explicit closed-choice support decision may create provenance. The normal model path sees at most four ranked candidates and cannot select outside the shortlist. Earlier recovery pipelines remain available for reproducibility/comparison. (#390)

The governing principle is explicit: **retrieval/reranking finds candidates; support validation establishes evidence.**

### Metadata Memory freshness and incremental exemplars

Metadata Memory revalidates when opened instead of allowing a cached empty projection to masquerade as current state. Backend scans page through live rows, failed refreshes retain the last successful page, interrupted reads are unavailable rather than empty, and bookmarked out-of-range offsets repair themselves. (#474)

Reviewed exemplars are reconciled incrementally by affected Record. Compatible evidence-context vectors can be reused, obsolete examples are retired, and disputed/invalid/unresolved/sealed second-opinion material remains excluded from trusted precedent. (#428)

## Pipeline Studio

Workflow purposes are now server-owned contracts describing category, consuming feature, input/output/authority semantics, and required guarantees. Strategies declare scholarly effects such as advisory computation, scope constraint, eligibility/provenance gate, transformation, generation, or evaluation. Retrieval/fusion/reranking/diversity are explicitly advisory rather than evidence gates. (#318)

The dedicated Strategies workspace supports filtering by family, computation, capability, scholarly effect, and workflow and shows where strategies are used. Stage cards/graph nodes expose phase/effect information. The Strategies table was later simplified into four intentional columns with typed input/output chips and improved keyboard/overflow behavior. (#318, #442)

Pipeline Studio uses a shared workspace architecture for Pipelines, Strategies, Executions, and Operations, with a graph-first editor, stage inspector, version details, persistent validation state, benchmark/compare workspaces, sticky pane behavior, and route/history state. (#333, #334)

Every executable strategy declares typed inputs/outputs and complexity. Each required input must resolve to exactly one valid explicit binding, graph data edge, or workflow input; invalid/missing/multiply-fed/wrong-type bindings block saving. Administrators can create blank workflow drafts, add fit-filtered stages, wire inputs, and inspect checks/latency/complexity before saving. (#368)

Pipeline analysis reports resolved wiring, stage/pipeline complexity, candidate/model-call bounds, observed latency with sample size/basis, and scope scaling where observations exist. Missing data stays missing instead of becoming zero. (#368, #379, #383)

Vector Store search executes from resolved wiring rather than only displaying a graph around a fixed plan. Evidence-recovery pipelines likewise honor explicit bindings while reporting when a rewiring bypasses the normal cELF support guarantee. (#370, #372)

Constant numeric tuning inputs, additional retrieval arithmetic ports, explicit ordering-only edges, and optional bounded parallel execution for safe independent store-search branches were added. These controls cannot alter provenance gates, access policy, reviewer decisions, or fixed support thresholds. (#375, #379)

Reviewer-evidence and recovery pipeline variants can be compared non-persistently against real source-unit projections, reporting overlap/behavior rather than inventing a scholarly “winner.” (#432)

## Semantic maps and relationships

Relationship maps and Pipeline Studio gained Compact/Standard/Wide spacing controls and clearer unavailable-vs-timeout fallback styling. (#322)

Record semantic maps and entity/relationship graphs gained zoom-invariant node/label/edge treatment and broader exposure from Record and Works. (#324, #325)

Semantic maps now use deterministic clustered/component-local layout, compact packing, search, node-kind filters, neighborhood focus, selection inspection, synchronized list selection, Record navigation, auto-fit/reset-to-fit, zoom-level decluttering, and stronger selected/related hierarchy. Repeated co-occurrence can affect edge weight but remains derived navigation rather than causal/scholarly evidence. (#337, #348)

Works uses the same canonical semantic-map presentation whether projections were already persisted or generated from current Records. Semantic graph/Record maps/neighborhoods/Work visual sources are persisted as rebuildable projections with indexed reads and reviewer-audience isolation. Missing maps calculate/save rather than appearing falsely unavailable. (#339, #391)

## Works and corpus-library experience

Works is now a corpus-library workspace with a shared header, clear **Loaded workspace** versus **Corpus database/search index** context, search/filter/sort toolbar, Cards/Compact modes, accessible selection, secondary menus, and a sticky wide-screen inspector or narrow-screen dialog. (#341)

Work counts deduplicate the same Record loaded through several local files/subsets while preferring a copy with unsaved edits. Reloading a clean collection/work replaces the earlier clean copy instead of silently adding a duplicate tab. (#344)

The Works data model separates cheap library summaries from expensive selected-work detail, pre-indexes annotation counts, and preserves full-corpus Create Site scope independently of active filters. (#352)

A shared-state regression that broke database synchronization while checking background upsert jobs has been fixed. (#482)

## Static research sites and TypeScript SDK

Administrators can create immutable research-site snapshots for one or more Works while keeping canonical Records separate from derived embeddings. Published sites support Works/Record browsing, metadata filters, annotations, search, and evidence-grounded Research. (#327)

A framework-neutral TypeScript DerridAI SDK exposes publication loading, storage, embedding/generation injection, citations, annotations, lexical/semantic/hybrid retrieval, MMR, evidence packets, and Research. Provider endpoint/API-key policy is injected by host applications rather than baked into the SDK. (#332)

Publication supports compact static/two-file output, a self-contained single-file local HTML mode with networking disabled, and an nginx Docker bundle with static serving, health check, and start/stop helpers. The nginx package needs neither the DerridAI API nor Node/Python at runtime. (#330, #335)

Readers configure Ollama or OpenAI-compatible providers locally, discover models, assign roles, and optionally remember credentials. API keys are never exported with the publication. Provider/embedding/generation failures degrade gracefully: keyword search continues, evidence remains visible, and diagnostics explain connection/CORS/model problems. (#345, #356, #330, #338)

nginx exports can optionally expose a same-origin /provider/ reverse proxy. Host loopback addresses map through Docker host-gateway, removing provider-side browser CORS requirements for that deployment mode while retaining streaming generation and an explicit security boundary. (#395)

Published sites can build a local semantic index in the browser. The compatibility-first default is pinned multilingual E5 with WebAssembly as the safe default and WebGPU opt-in. **Enable semantic search** downloads/caches the model, embeds Records, and persists the derived index in IndexedDB where available. Index identity binds publication/model/revision/vector-changing settings, and failures fall back to keyword search. (#356, #377, #381, #434)

Create Site can publish browser-ready multilingual-E5 vectors, preserve current database vectors, or omit vectors and let each reader build them. Browser-ready vectors are the recommended default. Exact embedding model/revision/variant provenance prevents mixing incompatible vector spaces. (#381, #466)

Browser inference uses smaller batches, disposes completed tensors, and yields between work chunks to keep rendering/progress/cancellation/input responsive. BGE-M3 remains an explicit advanced browser choice. (#434)

Create Site offers complete or reader-optimized Record metadata. Reader-optimized output remains cELF Core Record-compliant, omits the full FieldAssertion layer, retains all project-defined metadata values, records conformance/omission status, and carries compact authority summaries where assertions existed. (#350, #351)

Published sites can include selected installed DerridAI languages and support RTL, light/dark themes, high contrast, forced colors, landmarks, skip links, labelled controls, live status, and an accessible first-run tutorial. Keyword results safely highlight literal terms and can open at the first match; semantic/hybrid relevance does not pretend to be literal matching. (#338, #346, #347, #381)

Generated Research evidence markers are replaced with deterministic inline citations linked to the corresponding evidence item. (#476)

The built-in publication reference interface now has a Vue entrypoint/build while the older browser controller remains behind a compatibility adapter. The public SDK stays framework-neutral. (#479)

## Research

Live Research follows realtime job events instead of repeated 3-second HTTP polling. (#360)

Optional automatic Record-size-aware retrieval can scale candidate depth for unusually short Records, collapse adjacent same-document hits for reranking, then restore each Record as its own provenance-bearing evidence item. Existing evidence/reranker bounds remain; automatic sizing is off by default. (#392)

Research renders its frame immediately and loads history, pipeline choices, and answers independently. Drafts survive refreshes, failures have local Retry, and stale responses cannot replace current state. (#468)

## Realtime invalidation and progressive loading

DerridAI now uses a common live-data pattern: a committed mutation emits that a named resource changed; mounted queries invalidate/refetch; REST/GraphQL remains canonical. Realtime events never become authoritative state. Users/Roles were the first migrated surfaces. (#359)

Pipeline definitions/runs, Vector Stores, Metadata Memory, Response Library, saved responses, Metadata examples, storage summaries, and benchmark data now use the same invalidation model. Several manual Refresh controls were removed. (#362, #364, #365)

Search, Record, and Compare can show **Newer data is available / Load newer** instead of replacing what a researcher is currently reading. (#365)

Works/Record retain their frames, selection, and drafts during refresh. Vector Stores isolate collection loading from provider/storage-health failures, and request identities prevent slow stale responses from replacing current results. (#440)

Search now renders its shell/controls/results frame before the first read, retains visible content on refresh failure with local Retry, and no longer converts retrieval outages into “zero matches.” Visible rows retain the identity of the query that produced them. (#446)

Response Library retains content while archives load independently; Records shows placeholders and visible hydration failures. Languages independently loads dictionary/policy state while preserving drafts; Relationships independently loads trace/model data while retaining the graph. Accounts and Roles progressively refresh while protecting drafts. (#470, #475, #481)

Roles now uses the shared query cache, updates it on mutations, and no longer exposes a manual header Refresh button. (#483)

## Navigation, Settings, Metadata Schemas, Help, and shell UX

The sidebar has clearer brand/collapse/current-page treatment, better compact/mobile behavior, stronger focus states, and a clearable navigation filter. Expanded navigation no longer shows redundant tooltips when labels are visible. (#328)

Vue Router is now the sole navigation-history owner. Back/Forward follows actual browser history, including query-only changes, rather than a separate runtime snapshot list; tooltips identify destination titles. Later runtime-retirement work removed duplicate popstate ownership and hardened router/runtime resynchronization. (#405, #447, #450)

Toasts stack (up to five) instead of replacing one another. Message-dialog/toast callers moved to Vue hosts/composables, and disabled-control explanations are localized. (#409, #411, #450)

Settings is reorganized into Overview, Preferences, Research & review, Retrieval & indexing, AI & language services, Data & storage, Access & permissions, and Troubleshooting & recovery. Older URLs canonicalize to the new structure; retention explains canonical-vs-operational data boundaries; System/Corpus Data are linked rather than duplicated; workspace destruction is isolated in a danger zone. (#449)

Metadata Schemas now uses shared semantic form primitives, a grouped navigator and persistent field inspector instead of expandable table-row forms, progressive disclosure, responsive master/detail layout, and broader keyboard/reflow/theme/contrast/reduced-motion/French/accessibility coverage. (#452)

The Help Center is search-first/task-first with role-aware quick starts, responsive contents navigation, bookmarkable state, and a much broader glossary/Q&A covering current ingestion, review, evidence, pipelines, realtime behavior, provider queues, retention, backup/restore, and static publication. Administrator-only help remains hidden from Researchers. (#478)

## Accessibility

Search column resizing is keyboard-operable. The movable Record popout can be repositioned from the keyboard and now contains/restores focus correctly. The bulk metadata editor also contains/restores focus. Affected legacy tiny/removable controls meet a minimum 24×24 CSS-pixel target. (#492)

Published sites have dedicated coverage for themes, high contrast, forced colors, tutorial states, skip links, and narrow reflow. (#338)

Gloucester does **not** claim that these engineering sweeps alone establish complete WCAG 2.2 AA certification; larger/manual route-complete follow-ups remain explicitly tracked.

## Source ingestion, segmentation, and local data

Corpus segmentation now uses language-aware profiles for sentence, heading, speaker, quotation, and continuation rules. Documentary language is used when known with conservative Unicode-script inference otherwise. Coverage includes major Western-European conventions plus CJK, Arabic, Indic, Cyrillic/Greek, Hebrew, Armenian, Ethiopic, Myanmar, and Tibetan scripts. Segmentation engine/profile identity is retained as provenance. (#342)

Source-unit embedding requests and Chroma mutations are safely batched by configured/database limits; replacement/current projection rows are written before stale rows are pruned; providers must return one vector per requested unit. (#406)

Gutenberg local installation is now a verified SQLite text database at /data/gutenberg/gutenberg.sqlite3. Weekly archives stream into staging and atomically swap after verification, the transport ZIP is disposable after installation, the previous verified database remains usable during updates, downloads are resumable, and author discovery/acquisition can run from the local catalogue without Wikidata/provider network access. (#488)

Only small English/French spaCy models are bundled. Other languages use the existing administrator-managed digest-verified language-pack workflow. (#458)

## Performance, freshness, and concurrency

Completed enrichment Records are persisted individually instead of rewriting the full Record store after every completion, and review queue selections are shared/cached across REST and GraphQL. Component benchmarks showed large queue-selection improvements on synthetic 10,000-Record data, but Gloucester does not convert those measurements into a blanket end-to-end speed claim. (#419)

Record review decisions use Record-local writes/undo paths and cached aggregate derivation where possible. (#358)

Pending initial/retry/rerun enrichment is bounded. Reviewer-triggered metadata work, Research, and tools receive foreground scheduling at shared provider gates while background work is protected from starvation. Metadata-family checkpoint reuse requires exact dependency/output fingerprints and revalidation. (#430)

Selected source-block reads can use a disposable file-version-bound byte-offset index rather than repeatedly loading whole authoritative JSONL. More preparation stages use conditional Record deltas/three-way reconciliation so concurrent human edits and authority survive. (#439)

Automatic retries/reruns/requeue clearing and validation handoffs reconcile against current canonical rows rather than restoring stale whole-corpus snapshots. Document Intelligence freshness now includes Record identity/order/source locators/documentary fingerprints instead of only concatenated text. (#444)

Automatic final validation uses short coordinated snapshots with bounded conflict retries, preserving concurrent text edits, metadata decisions, retirement/topology changes, and cancellation while keeping Review available where safe. (#448)

Initial enrichment queue creation and Record completions increasingly use transactional/batched reconciliation. Optional reviewer assistance such as source reads, advanced JSON formatting, autocomplete, and precedents is demand-gated to visible/active surfaces. (#453, #455, #464)

Canonical snapshots/summaries, semantic caches, pinned schemas, loaded-model caches, provider-switch epochs, and build deletion have stronger coordination so late worker/cache results cannot replace newer state. Slow source extraction/staging and per-build checkpoint I/O use narrower critical sections; late checkpoint writes cannot resurrect a deleted build. (#484, #491)

## cELF 1.0 clarification

cELF is now framed explicitly as a durable lexical/documentary information architecture rather than a retrieval-first descendant of the earlier cERF concept. The specification distinguishes a **Core documentary provenance spine** from profile-scoped provenance graphs. (#412, #415)

EvidenceAcquisitionRun is a first-class, mechanism-neutral audit object for one bounded evidence-acquisition operation. RetrievalRun remains specifically computational search; human selection, direct reference, deterministic lookup, import, or other evidence-location mechanisms are not mislabeled retrieval. (#412, #415)

GenerationRun provenance remains distinct from the direct GeneratedClaim → SupportBinding → EvidenceRef support relationship. Pipeline Studio traces may supply lower-level computational provenance without becoming cELF semantic objects. (#412, #415)

EvidenceRef now requires exactly one authoritative documentary locator without permanently limiting cELF extensions to literal record/source_span field names. Namespaced extensions must resolve unambiguously and reproducibly to one SourceDocument; convenience/display locators remain non-authoritative. (#420)

Retrieval scores, embeddings, caches, semantic projections, browser indexes, Pipeline Studio diagnostics, and realtime UI state remain derived/operational rather than canonical scholarly authority.

## Legacy frontend runtime retirement

A large portion of Gloucester's code churn is architectural rather than independent product behavior. Navigation history/popstate/URL state, notifications/dialogs, work/merge/OCR/bulk/history/job/LLM dialogs, shell preferences, provider profiles, Compare, Search, Records, Record, file import/persistence/restore, backup/jobs/database presence, semantic-map sources, store export, PDF linking, Record cleanup, and corpus hydration have progressively moved from the legacy runtime to router-owned navigation, Vue hosts/composables, Pinia/shared state, and focused domain modules.

Visible consequences are documented above: browser-native Back/Forward, stacked toasts, localized disabled reasons, progressive/query-backed loading, fewer stale-state races, and preserved Record/file/store workflows while compatibility code shrinks.

PR #494 moves record-file commands, store export, corpus hydration, PDF linking, Record cleanup, and the Record workspace itself onto shared state with **no intended behavior change**.

## Compatibility and upgrade notes

- Automatic evidence recovery defaults to **evidence.recovery.cascade@2**; older pipelines remain available.
- Model-proposed absence is no-value state rather than placeholder metadata.
- Metadata schema format 3 adds repeatable associated groups.
- Semantic segmentation remains the default topology; fixed SourceUnit grouping and synthetic Page grouping are opt-in policies.
- Text review can become available before all automation finishes only after documentary topology has been safely validated.
- Corpus provider concurrency accepts 1–64 subject to the shared process-wide provider limit.
- Back/Forward uses actual browser/router history.
- Several workspaces no longer expose manual Refresh because realtime invalidation/window focus revalidate retained content.
- Failed Search is an error, not zero matches.
- Automatic Record-size-aware Research retrieval remains opt-in.
- Published-site provider credentials are reader/local configuration and are not exported.
- Static sites can ship browser-ready vectors, current database vectors, or no vectors.
- Reader-optimized site exports retain all project metadata values while omitting the full FieldAssertion layer.
- Only small English/French spaCy models are bundled; other language packs remain managed.
- Gutenberg's installed artifact is the verified SQLite text database; the download ZIP is disposable.
- host.docker.internal works with native Docker Engine through host-gateway mapping.
- Chroma vectors, semantic projections, browser indexes, caches, Pipeline Studio metrics/traces, and realtime state remain derived/rebuildable or operational.

## Release direction

Gloucester makes the separation of concerns more visible to users:

- researchers can review while automation continues;
- retrieval can rank candidates without silently deciding evidence;
- pipelines can expose computation without acquiring scholarly authority;
- browser indexes can accelerate portable publications without becoming the corpus;
- realtime events can keep pages fresh without becoming canonical state;
- caches can make review fast without overriding revisions or human decisions;
- autonomous publication can be explicit without pretending it was human review.

The core rule is unchanged: **AI and retrieval may propose, rank, and accelerate; canonical scholarly authority and exact evidence/support remain explicit and auditable.**
