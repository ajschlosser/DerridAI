# 0.80.6 — Danvers

Danvers is a rapid consolidation release covering the work merged after
`v0.80.5 — Cambridge`. It turns the post-Cambridge Corpus Builder work into a
more coherent source-to-record-to-claim workflow: source acquisition and
segmentation are more reliable, review is more focused and evidence-aware,
metadata and Research memory are more explicit about authority, and provenance
is easier to inspect without flattening canonical records into derived search
or memory projections.

## Provenance, cELF, and publication integrity

- Reworked Record traceability into a bounded visual provenance map that keeps
  source, metadata, evidence/support, and generated-claim relationships visible
  without treating navigation history as the graph itself.
- Unified evidence-marker parsing between citation rendering and durable
  support persistence, preserved zero-valued source offsets and block/unit
  locators, and deduplicated equivalent source-span observations.
- Aligned the repository specification and documentation to **cELF
  (Capta-Enriched Lexical Format)** while retaining existing wire-format,
  module, and `/api/derridai/*` compatibility identifiers.
- Added one canonical reviewer-decision domain operation for single and batch
  metadata decisions, including dispute handling, blind-second-opinion
  deferral, and post-save memory recording.
- Made build warnings first-class publication provenance: warnings can be
  acknowledged without being deleted, record-specific warnings follow their
  records, and build-wide warnings plus acknowledgements follow the immutable
  publication.
- Added sparse, provenance-preserving Zstandard corpus ledgers
  (`.jsonl.zst`) with explicit integrity checks for current assertions,
  evidence pointers, source spans, and epistemic state while retaining legacy
  plaintext ledger compatibility.

## Source acquisition, page structure, and segmentation

- Modernized Source intake and digital-library search, including accessible
  Gutenberg/Wikisource search, whole-work Wikisource imports, bounded and
  resumable Gutenberg catalogue/archive workflows, safe redirect handling, and
  clearer import progress and recovery.
- Fixed Gutenberg resume behavior when the local archive is already complete,
  including 416 handling, resume/redownload controls, and unpacking without
  unnecessary re-download.
- Added deterministic printed-page detection for text sources and a
  model-assisted fallback in which the LLM may only select real candidate
  lines; deterministic sequence validation remains authoritative.
- Added configurable source-unit policies for sentence, paragraph, line,
  character, and grouped-N paragraph/sentence units, with live previews and
  derived-source provenance.
- Made automatic source units the default way to honor requested record sizes:
  oversized paragraphs are divided into smaller units, record-size ceilings
  constrain sentence snapping, and heading-like boundaries no longer trigger
  destructive joins.
- Fixed the segmentation failure where one source unit larger than the ceiling
  could cause the rest of a document to collapse into a single enormous
  record, and made normalization substantially faster on small-target builds.
- Added source-size guidance and record-sizing rulers/presets so users can see
  when the current unit policy cannot realistically satisfy the requested
  record length.
- Added deterministic front-matter prefill for work-level metadata such as
  ISBN, publication year, translator, publisher, and publication place, with
  origin/confidence information and suggestion handling.
- Added build pause/resume/delete, source delete, and non-blocking source-load
  feedback.

## Record review, evidence, and metadata

- Redesigned Corpus Builder review around stable metadata adjudication:
  required fields first, in-place folding after a decision, consistent Confirm
  / No value actions, keyboard progression, and one shared bottom decision
  dock for normal and Focus review.
- Rebuilt Focus View from the same reader, metadata, evidence, source, and
  decision components used by the main review workspace so review semantics do
  not fork between modes.
- Added review-in-context with bounded neighboring records, clearer queue rows,
  publication blocker deep links, next/back issue navigation, and more reliable
  queue switching after validation and text review.
- Added deterministic and optional LLM evidence suggestions. Suggestions rank
  candidate spans but never bind evidence; the reviewer remains responsible
  for the final evidence decision.
- Added select-all evidence, direct confirmation with selected evidence,
  reviewer-own-knowledge citation, citation of units from other records, and an
  always-available "Why this value?" trace matrix.
- Prevented structured-output residue such as evidence IDs, confidence
  fragments, and reasoning text from leaking into scholarly list-valued
  metadata at either the API or review boundary.
- Kept operational bookkeeping keys out of scholarly metadata review and
  assertion migration while still allowing schema fields with the same names
  when deliberately configured.
- Changed structural split/merge/create operations to retire affected Records
  and mint new identities with explicit lineage, text conservation, re-review,
  and enrichment rather than mutating record identity in place.
- Added work-wide schema fields and `work_metadata` handling for values that
  apply to an entire work rather than each individual record.

## Memory, precedents, Research, and schemas

- Added source-span-matched metadata prefill from reviewed precedents. Automatic
  prefill requires strong agreement from multiple earlier records, keeps human
  authority unresolved, and records weaker matches as reviewer hints.
- Reworked Research memory so cached-response guidance is retrieved by question
  similarity and gated by durable grades, while cached claim guidance uses
  validated claims whose supporting records are rechecked against the current
  run's evidence.
- Added schema-driven precedent retrieval controls for correction quotas and
  stable-field-ID matching conditions; removed hard-coded per-field precedent
  limits and fixed-list lexical fallbacks.
- Added read-only "Similar reviewed precedents" and "Research claims citing
  this record" panels, including stale-binding visibility.
- Redesigned Metadata Memory as a filterable table with clearer relationships
  to System Data metadata examples and the semantic-memory outbox.
- Redesigned Metadata Schemas as a compact table/editor workspace with grouped
  field editing, policy chips, save-state protection, import/export/duplicate
  actions, retrieval controls, plain-language help, and improved field-form
  layout.
- Added a Research hybrid preset that combines ordinary retrieval with the
  researcher's selected evidence, and fixed locale filtering so records with
  no language value are not silently discarded as "no evidence."
- Added a searchable bilingual Help Center explaining where configuration and
  review decisions affect later system behavior.

## Corpus Builder architecture, providers, and system configuration

- Continued decomposing `PdfCorpusBuilder.vue` into dedicated Enrichment,
  Metadata, Advanced, Review Queue, Review Toolbar, Evidence, Source, Focus,
  and sizing components while keeping mutation/provenance ownership in the
  existing controllers and composables.
- Reorganized the visible Corpus Builder around Source, Structure, Enrichment,
  Metadata, Advanced, Review, and Publication readiness rather than exposing
  internal machine stages as the primary workflow.
- Added durable server-owned embedding defaults shared by vector-store creation,
  metadata exemplars, and related semantic projections, with provider-profile
  resolution, health diagnostics, and rebuild behavior when an embedding
  contract changes.
- Added metadata-exemplar diagnostics and forced projection tooling while
  keeping the exemplar collection explicitly derived and rebuildable.
- Redesigned LLM Providers around progressive disclosure and fixed actions that
  previously discarded unsaved edits.
- Added dedicated server-side audio transcription endpoint/model/key settings
  and reachability testing.
- Added closable shared notice stacks and page-level tooltips that remain
  visible across clipped panes and modal top layers.

## Quality and compatibility

- Preserved canonical `FieldAssertion`, Record revision, source/evidence, and
  publication authority while keeping Chroma collections, precedent indexes,
  response/claim memory, and UI caches derived and rebuildable.
- Expanded English/Canadian-French strings, Storybook states, Vitest coverage,
  Playwright review/source/library workflows, WCAG 2.2 AA sweeps, backend
  regression tests, contract checks, Ruff, mypy, and repository formatting
  gates across the new surfaces.
- Kept existing compatibility boundaries where required, including legacy
  publication decoding, current route names, and derived status projections.
