# 0.62.15 — Patient Pelican

Follow-up to 0.62.14, from watching a real build stall.

- **The build says what it is waiting for.** The progress bar only moves when a stage finishes, and the first model call can take minutes (a 12 GB model has to be loaded first), so it looked frozen at 3%. A line under the stepper now reads "Waiting for <model> to load into memory (1 min 48 s)…", then "<model> is working on the record boundaries (12 s)". The server checks Ollama's `/api/ps` to tell loading from working; for other providers it says "working", and if Ollama cannot be asked, plain "waiting".
- **A model load is no longer abandoned, and the build survives a dropped connection.** With `qwen3.5:4b` the document-structure step fell back to the PDF's own properties ("Server disconnected without sending a response"). The provider warm-up sent a chat with no `num_ctx` (so Ollama loaded the model at its 262144-token default) and gave up after 60 seconds; Ollama aborts a load whose requester has gone, which also failed the build's own first call waiting on the same load. Warm-up now loads with the profile's `num_ctx` and waits as long as the load takes (up to 15 minutes), and model calls retry a dropped connection three times with growing pauses (3, 8, 15 s). Timeouts and bad answers are not retried.
- **"Analyse the document again"** in Edit document metadata asks the model for the document details again and fills only fields that are still empty; nothing entered by hand is changed.
- **The model list is back on the LLM Providers page.** "View models (N)" opens a searchable list showing each installed model's size and quantization, with "Use model". It was not removed for accessibility: the page was rebuilt in Vue (0.62.x) with a plain field and suggestion list, and the list was not carried over. The model mode (Auto router / Discovered / Manual) and model kind (Any, General/chat, Reasoning, Coding, Fast/small) selectors for OpenAI-compatible profiles, also lost then, are back. The list is a dialog of labelled buttons with the match count announced as you filter; axe finds no violations.
- **The enrichment "highlighted changes" now exist.** After a pass changes a record it is reopened with "Metadata enrichment added, replaced, or disputed metadata; review the highlighted changes.", but nothing highlighted them: the record kept the details (`metadata_enrichment_history`) and the interface never showed them. The Metadata tab now opens with "Changed by the last enrichment pass": values added, values replaced (old value struck through, with "Restore previous"), and disagreements where the pass left the current value and proposed another (with "Keep current" and "Use proposed"). A change drops off the list once you decide that field. It uses the theme tokens; axe finds no violations in light or dark.
- **The initialization panel's end-to-end test** now expects the inline panel introduced in 0.62.14 instead of a modal.

## What is not done

- Restarting Ollama during a build still interrupts the call in flight; it is retried, but a restart longer than about 26 seconds still ends in the fallback. Use "Analyse the document again".
- The Ollama environment sets `OLLAMA_CONTEXT_LENGTH=262144`; any client that does not send its own `num_ctx` loads models at that size. Consider lowering it.
- The Playwright test `record-find is WCAG 2.2 AA clean` is flaky (it passed on retry in CI and 2 of 3 runs here); it is unrelated to these changes.
- Not run against a live Ollama or FreeLLM; the model list was checked against the mock API only.

## Validation

pytest 363 passed; `ruff`, `mypy`, `vue-tsc` clean; Vitest 302 passed; the Playwright specs for the Corpus Builder fixes, the providers model list and the app views pass on the desktop project apart from the flaky test above. The full Playwright suite was not run.
