# 0.80.5 — Cambridge

Cambridge is a consolidation release covering the work merged after
`v0.80.0 — Beverly`. It completes the canonical FieldAssertion migration,
tightens metadata review and Research configuration, substantially decomposes
and modernizes Corpus Builder, aligns the repository specification with the
published DERRIDAI Core Specification 1.0, and introduces the first walkable
DERRIDAI object-graph explorer.

## Canonical metadata and review

- Completed the remaining `FieldAssertion` migration across the Record
  Inspector, Research evidence presentation, review acceptance, confirmed
  absence, evidence assignment, human edits and overrides, source-quality
  gating, manifest inheritance, enrichment ownership, editorial memory,
  settlement, retry eligibility, issue summaries, and enrichment metrics.
- Preserved independent derivation, evaluation, authority, value-state,
  confidence, evidence, revision, and stable field identity semantics. Human
  confirmation no longer erases model derivation, evidence, or confidence.
- Kept `metadata_field_status` as a compatibility/migration/telemetry
  projection rather than scholarly authority.
- Added schema-derived allow/edit policy, stable custom-field identity,
  assertion-aware source-quality and manifest checks, and stronger regression
  coverage for custom fields and migration behavior.
- Improved concurrent review reliability by serializing and rebasing
  same-record mutations, reconciling optimistic edits with authoritative
  server state, and routing validation issues into actionable review queues.
- Prevented structured-output transport syntax from leaking into scholarly
  metadata values and made POS/NER schema guidance clearer without changing
  the raw stored tag values.
- Added clearer field-policy presentation for requiredness, human decision,
  evidence, confidence, memory policy, derivation, authority, confirmed
  absence, override, unresolved, and invalid states.

## Research and prompt metadata

- Added a per-run Research prompt-metadata policy with independently
  configurable Evidence, Context, and Record channels.
- Resolve stable FieldAssertion IDs or field names server-side while keeping
  source identity, citation, and evidence text deterministic and non-optional.
- Persist prompt-metadata selections through reruns and preserve existing
  behavior as the default when no explicit policy is supplied.
- Promoted Prompt metadata to the main Research setup surface, including
  channel counts and direct access to the metadata matrix.

## Corpus Builder architecture and UX

- Refactored the former monolithic Corpus Builder frontend into focused source,
  provider, build-lifecycle, review-workspace, review-navigation,
  review-decision, text-review, boundary-review, metadata-review, and
  publication controllers.
- Split the frontend corpus API into source, build, record, review, metadata,
  and publication clients while preserving the existing `pdfCorpusApi`
  compatibility boundary and server routes.
- Reduced responsibility concentration in `PdfCorpusBuilder.vue` and made
  source-media behavior capability-driven rather than scattering PDF/audio/
  image checks through the workspace.
- Unified reviewed-text editing and touch-up behavior across normal and focus
  review, centralized review keyboard commands, and improved queue navigation,
  focus history, publication targeting, and optimistic-state handling.
- Made nullable or unreported evidence confidence remain nullable rather than
  presenting it as numeric zero.
- Exposed canonical FieldAssertion history, retained alternatives, and active
  disputes in metadata review.
- Modernized supporting Corpus Builder surfaces with shared design tokens and
  controls, media-neutral source/readiness presentation, high-zoom and
  long-string resilience, forced-colors support, and expanded Storybook and
  accessibility coverage.

## DERRIDAI specification and traceability

- Aligned `SPECIFICATION.md` with the published DERRIDAI Core Specification
  1.0, including the four-layer source-to-claim model, the normative 13-object
  entity/cardinality model, FieldAssertion's four epistemic dimensions,
  EvidenceRef locator modes, EvidencePacket semantics, SupportBinding rules,
  advisory-memory boundaries, conformance profiles, invariant mappings, and
  stable requirement IDs.
- Reclassified extraction units, metadata-schema/editor objects, generic
  relations, storage projections, retrieval candidates, packet wrappers,
  validation results, and grading results as implementation artifacts rather
  than normative DERRIDAI semantic objects.
- Added a single backend DERRIDAI 1.0 type/cardinality registry and authenticated
  model/graph endpoints.
- Added a Record Inspector Traceability tab that lets researchers walk from a
  focal object to any retained adjacent object, re-center on that object, and
  continue traversing without treating traversal history as the graph itself.
- Added both instance and normative-model traversal, inverse relationship
  labels, cardinalities, back/forward history, branch preservation, and visual
  distinction between normative DERRIDAI edges and DerridAI application links.
- Added owner-scoped reverse provenance lookup from Record to SupportBinding to
  GeneratedClaim, with current-record revalidation and visible stale/unresolved
  state.

## Documentation, licensing, and engineering

- Added repository-wide Prettier ownership, EditorConfig, formatting CI,
  clean-checkout setup guidance, expanded contributor documentation, current
  FastAPI/router/corpus/provenance architecture documentation, and stricter
  handoff validation.
- Added README translations in Canadian French, Nicaraguan Spanish, German,
  Italian, Hungarian, Russian, Hindi, and Arabic with reciprocal language
  navigation.
- Restored the Hungarian, Italian, and Russian README translations after the
  final merge sequence inadvertently dropped those already-merged files.
- Added the GNU Affero General Public License v3 and standardized project
  licensing as `AGPL-3.0-only`.
- Retained and expanded frontend typechecking, Vitest, Storybook, Playwright,
  legacy DOM characterization, WCAG/axe, Ruff, mypy, backend regression, API
  contract, and repository-format quality gates.
