# 0.62.2 — Vexing Vixen

A patch release for the sidebar, the language screens, and researcher text policy generation. No data migration is needed.

- **Sidebar at sign-in:** the menu used to come from the runtime's shell snapshot, which starts empty and fills only after the runtime's slow bootstrap. Until then the sidebar showed one primary item and an already-open "More tools" holding only the Users, Roles, and Languages entries, and clicking Operations fixed it by accident (it re-navigates home, which republishes the snapshot). The navigation list is now published as soon as a user exists, nothing is drawn until it is known, and it is cleared on sign-out. "More tools" is open by default for administrators; a choice you make is remembered in that browser.
- **No regional special cases:** the fleur-de-lis flag option and every rule that chose a flag or name from a locale code are gone. A language's name and flag are plain stored data, built-ins are seeded from one table, the French name is "Français", and the translation prompt has no locale-specific brief. The locale code `fr-CA` is unchanged. Older release notes still describe the earlier wording.
- **Policy card layout:** the forbidden-term badges sit directly under the explanatory text in the left column, followed by the add/save editor, instead of a full-width row that made the card grow. The provider and generate controls stay on the right, and a long badge list scrolls.
- **Policy generation in the selected language:** the request names the installed language (for example "Français (fr)") and forbids other languages, asks for terms in six categories (vulgarities, sexual insults, racial/ethnic, religious, homophobic/transphobic, and ableist slurs, at least three each), audits every candidate with a narrower "is this a word of this language?" question, and requires terms that also appear in another installed locale's policy to be affirmatively confirmed. Only the categories still short are requested again, up to three rounds, with the rejected terms listed. Wrong-language terms are never saved. If a category is still short the policy is saved with a "Coverage is incomplete" note; fewer than eight acceptable terms is refused with an explanation. The card shows the attempt count and how many terms the language check removed. The check uses the same model as generation, so it reduces the problem rather than removing it.

Policies generated before this release are not changed. Regenerate a policy to get the new checks.

## Validation

Linux, Python 3.12, Node 22:

- `pytest -q`: 188 passed. `ruff check api/app` and `mypy`: clean.
- `npm run lint`, `typecheck`, `test:unit` (63), `build`, and `build-storybook`: pass.
- Playwright + axe: 42 passed (Storybook on port 16006, one worker, CI's single retry).
- Regression tests fail without their fixes: sidebar completeness at sign-in and remembering the toggle, the policy card structure, and the language audit (disabling it fails five generation tests).
- Docker `web` and `api` images were built from this branch and run as a scratch stack on other ports. With the runtime's provider fetch delayed by 3 s, the sidebar showed 8 primary and 10 "More tools" items at 200 ms. English and French policies were generated through the Languages screen with a local `gemma4:e2b`: the French policy had 26 terms, none also in the English policy, from 2 attempts with 6 terms removed by the language check. The same model with the previous single-shot prompt returned 14 English-policy words among 20 "French" terms. That is one model and one run each; the model's output varies between runs.
- Not run: the production Docker stack (only a scratch copy was), and other models or languages.
