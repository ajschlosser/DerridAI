# 0.70.0 — Amesbury

This release covers roughly 280 commits and 48 merged pull requests since 0.62.19, contributed by multiple agents and the project owner working in parallel. Because of that scope, this note groups changes by theme and names the source branches/PRs rather than asserting implementation detail this note's author did not personally verify for every change; the runtime-decomposition and vocabulary-rename work described in detail below was written and verified by this note's author, the rest passed CI under its own authorship at merge time.

## Legacy runtime decomposition

`web/src/runtime/runtime.js` continued its multi-session decomposition into modern Vue components and domain modules (`claude/runtime-refactor-2` through `-25`, PRs #71–#117 among others):

- The dashboard, PDF Explorer, and response cache views were converted from `v-html`-rendered HTML-string generators into real Vue `<script setup>` components with identical markup, ids, classes, and behavior (verified against a 131-scenario legacy-DOM baseline and a full Playwright/axe e2e suite).
- With all three converted, the now-dead `RuntimeSurface.vue` host component, and the two view files (`CorpusView.vue`, `SystemView.vue`) that had never actually been wired into the router, were deleted.
- Records, Search, Compare, Works, Vector Stores, Settings, and other surfaces were migrated to native Vue views and composables across earlier sessions in this range; a per-file audit of `legacyCompat.js`/`translateLegacyDom` found it still load-bearing (it translates any remaining `v-html`-generated markup into French) and left it in place, rather than deleting it prematurely.
- `web/src/domain/navigation.ts` and related dialog modules (`workDialogs.ts`, `appLifecycle.ts`, `jobDialogs.ts`, `pdfLinking.ts`) had their remaining direct legacy-render calls replaced with `window.dispatchEvent(new CustomEvent("derridai:*-refresh"))` bridges to the Vue-owned views that now mount `#main` themselves.

## Assertion-status vocabulary aligned with the DERRIDAI Core Specification

The corpus builder's field-assertion status vocabulary was renamed to match `SPECIFICATION.md` exactly: `llm_inferred` → `model_inferred`, `human_confirmed_absent` → `confirmed_absent`, across the backend, frontend, and both locale modules' key names (the human-readable label text, e.g. "LLM inferred", is unchanged UI copy). A lazy, read-time migration normalizes any existing persisted build/record/checkpoint data still carrying the old vocabulary, the same way `_with_start_inference` already backfills an older asset's missing field.

## Corpus Builder decomposition, started

`api/app/corpus_builder.py`'s `PdfCorpusBuildManager` (previously ~6,800 lines, ~200 methods with no internal section markers) began a phased extraction into smaller, spec-aligned modules. The first cluster, publication and text touch-up, moved its pure logic (the touch-up prompt template, the publishable-records filter, and the publication-readiness blocker chain) into `corpus_publication.py`; the manager's methods now call those free functions instead of duplicating the logic inline. The remaining, larger clusters (segmentation, metadata/FieldAssertion, human review) are scoped but not yet started; see `PROGRESS.md` for the full plan and recommended order.

## What is not done

- The `PdfCorpusBuildManager` decomposition is one cluster of roughly seven; segmentation and metadata/FieldAssertion, the two largest and most spec-relevant clusters, have not been started.
- `legacyCompat.js`'s `translateLegacyDom` remains in place; a separate, small hardcoded-string i18n gap it cannot fix on its own (`dashboardCharts.ts`/`recordPresenters.ts`'s "no data yet" empty-state text) was logged in the temporary decomposition handoff but not fixed in this release.
- `PdfCorpusBuilder.vue` (8,186 lines) and `PdfCorpusRepository`/`PdfCorpusBuildManager`'s remaining clusters are the largest monoliths left in the codebase.
