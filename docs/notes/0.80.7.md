# 0.80.7 — Exeter

Exeter is a focused follow-up to `0.80.6 — Danvers`, covering PRs #219–#227:
specification-name alignment, faster and more evidence-aware Record Review,
a semantic-retrieval reliability fix, and a renaming pass that unifies every
remaining reference to the format's name.

## Specification and terminology

- Renamed the specification from **Capta-Enriched Lexical Format** to
  **Capta-Enhanced Lexical Format** everywhere it appears — `SPECIFICATION.md`
  (including the non-normative terminology note, which now glosses
  "Enhanced" instead of "Enriched"), `docs/notes/0.80.6.md`, and the
  in-app bilingual Help Center. The acronym **cELF** is unchanged.
- Fixed a pre-existing drift where the Help Center's "What is DerridAI?"
  answer (en-US, fr-CA, and the frontend's English defaults) called the
  format the **Capta Epistemological Ledger Format**, inconsistent with
  `SPECIFICATION.md`'s canonical name. All three now say **Capta-Enhanced
  Lexical Format**, matching the specification (PR #219 had already aligned
  `SPECIFICATION.md` itself to a single expansion; this release finishes
  that alignment across the remaining surfaces and settles on the final
  "Enhanced" wording).

## Record review and evidence

- Cited-elsewhere spans (`external_block_ids`) now count as evidence
  throughout the review UI — the field list, the Evidence panel, source
  highlighting, and optimistic save — via a shared helper, and the
  enrichment prompt lists each source block by ID so the model can cite the
  block that supports its answer in `with_value` mode. Removed the
  hard-coded "Jacques Derrida" author fallback in citations (PR #220).
- Answer evidence in Research now links back to Record View, the
  relationship map, and the cELF model; added a dedicated relationship
  browser page at `/relationships` (reuses the traceability explorer, with
  a record-ID picker and nav entry) (PR #221).
- Confirming a value, confirming no value, and batch suggestions now
  release the field immediately instead of blocking the UI for 2–3 seconds
  on the server round trip: no "Saving…" state, neighboring fields stay
  enabled, and focus advances at once. Failures still surface an error and
  roll back via a record refresh; a queue-ordering guard
  (`RecordMutationQueue.hasQueuedBehind()`) stops an older response from
  overwriting a newer queued save (PR #222).
- The record-context reader now fits neighboring records by real rendered
  layout (alternating before/after from the active record, then centering
  it) instead of a character-count estimate, which previously left small
  records in narrow columns without neighbors; the column's max height now
  scales with the viewport. The metadata panel's Evidence button now opens
  the Evidence tab directly (previously opened Source) (PR #223).
- Polished the LLM touch-up notice (info tone instead of an amber warning,
  wrapping description instead of an ellipsized line) and added a primary
  Save button beside Clean text in both text editors, with Ctrl/Cmd+S in
  the main review workspace (PR #224).
- Redesigned the field-level "Similar reviewed precedents" panel: a
  disclosure toggle with count, skeleton loading, retry on error, and a
  warning callout when retrieval fell back to lexical matching. Precedent
  cards are now kind-coded with a similarity meter; corrections read
  "Model said ~~x~~ / Reviewer chose y"; confirmed absences are explicit;
  unbound excerpts are flagged (PR #225).
- Record Review's precedents panel now reuses metadata enrichment's
  existing per-field retrieval instead of repeating the search each time
  the panel opens, and ranks the record's own source blocks against each
  precedent's reviewed evidence so adopting a precedent surfaces where
  *this* record may support it. Only references (exemplar IDs, similarity,
  candidate block IDs) are cached on the record — never another record's
  value or evidence text — and stale or hidden precedents are counted as
  `stale_count` rather than shown from a stale copy (PR #226).
- Added "Accept all suggestions and publish" to the Corpus Builder header:
  available once a build has finished processing and until a publication
  exists, gated by one inline confirmation. It publishes every non-rejected
  record with every suggested field value accepted, skipping human-review
  gates for unreviewed suggestions specifically — text-conservation errors,
  an empty publication, human-confirmed/overridden/disputed values,
  rejected records, and out-of-vocabulary proposals still block or are
  excluded (PR #227).

## Metadata retrieval reliability

- Fixed a crash in the semantic precedent/exemplar retrieval path where
  Chroma's `embeddings` query result could come back as a plain list
  wrapping a numpy-array batch rather than a top-level array. The previous
  `hasattr(embeddings, "tolist")` guard missed that shape, so a raw numpy
  row reached `_mmr`/`_cosine` and any boolean check on it raised `ValueError:
  The truth value of an array with more than one element is ambiguous`.
  Reviewers saw this surface as a broken "Suggest spans" / precedent
  fallback message. `_candidate_rows` now recursively normalizes any
  numpy-like value to plain Python lists before use
  (`metadata_exemplar_retrieval.py`).

## Quality and compatibility

- Added a regression test reproducing Chroma's list-of-ndarray embeddings
  shape with a numpy-free fake array, asserting `_candidate_rows` never
  lets a numpy-like value reach a boolean context.
- No wire-format, module, or `/api/derridai/*` compatibility identifiers
  changed; the specification-name and Help Center changes are text-only.
