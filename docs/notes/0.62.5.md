# 0.62.5 — Iterative Ibis

Metadata enrichment can now run as a chain of passes, and you can keep reviewing while it runs.

- **Chained passes.** The Run metadata enrichment again dialog has a Passes control: one pass, or a chain of 2 to 10. A chain stops early once a pass finds nothing new. When a run finishes, Run another pass starts the next one.
- **Review stays open.** Review actions were locked while a re-run was in progress, and the re-run wrote back a stale copy of every record after each one, which would have replaced edits made in the meantime. Passes now merge into the current record, skip records whose text you changed, and never touch a value you confirmed or overrode.
- **Decisions by confidence.** When a pass disagrees with an existing value, a proposal at 0.75 confidence or higher that leads by at least 0.10 replaces it; an existing value that clearly leads is kept; anything closer keeps both values as a disagreement for you to resolve. The same disagreement is not raised twice.
- **Only real disagreements.** A proposal that restates the existing value (different case or spacing, a number within 0.05, or a list that shares at least 60% of its items) is treated as agreement, and the model's own confidence scores are never disputed.
- **Learning.** Each pass is given how you treated earlier proposals in this build: accepted and rejected counts per field and a few rejected proposals to avoid repeating. Discourse role and region type conventions confirmed in at least two builds, with two or more confirmations each, are shared with new builds. Names such as speaker and position holder stay in the build they came from.
- **The build stays running.** Every review action revalidates the build, and during a pass that used to move it to Awaiting review, so the workspace lost the run and a second pass could be started alongside it. A running pass is now preserved through review actions.
- **Status in the workspace.** A status bar in the review workspace announces the running pass, shows progress for the current pass, and offers Stop enrichment and, afterwards, Run another pass. New strings have English and French keys.

## Validation

Linux, Python 3.12, Node 22, on the branch after merging `master` at 0.62.4:

- pytest: 208 passed, including `tests/test_enrichment_cycles.py`. `ruff` and `mypy` passed.
- Vitest: 147 passed. `eslint`, `vue-tsc`, the production build, and the Storybook build passed.
- Playwright with axe (WCAG 2.0 to 2.2, A and AA): 98 passed, including the four states of the pass status bar and the dialog's Passes control (axe, target size, reflow at 320 px, keyboard focus, and the accessibility tree). The first run after starting the Storybook dev server cold timed out on six existing Corpus Builder workflow tests at the 5 second expectation limit; the same specs then passed on every rerun.
- Live: a real build and a two-pass chain against Ollama (`gemma4:12b`) on a small synthetic PDF, with a value confirmed by hand while the first pass was running. The confirmed value survived, the build stayed running, the second pass found nothing new so the chain stopped, and the one recorded disagreement was a genuine one. This run found the two problems described above (the build leaving the running state, and disputes over model confidence scores and near-identical lists). It covered a single record, so replacement by confidence and the cross-build learning were exercised only by the unit tests.
