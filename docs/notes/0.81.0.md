# 0.81.0 — Fall River

Fall River is the first consolidated release after **0.80.7 — Exeter**. It rolls the post-Exeter work on `master` into a release centered on evidence-aware review, whole-document intelligence and semantic maps, versioned Pipeline Studio execution, schema-driven metadata, safer source ingestion, stronger provenance gates, modernized navigation/help/accessibility, operational retention controls, and threaded annotations.

The release baseline is annotated tag `v0.80.7` at `bc9415d6736bd06d2756851b9ef7a70bb0992cf1`. The release branch starts from `master` at `87678aa8a1a17d257ef780b22db0720fd1abb5d2`. The final release tag must be `v0.81.0`, annotated with `0.81.0 - Fall River`, and must point to the final release commit after this PR is merged.

## Release identity and build versioning

- The application version is now **0.81.0** with codename **Fall River**.
- Browser/API build labels combine the semantic version, codename, and git commit as `0.81.0 - Fall River (<commit>)` when a commit is available.
- The sign-in screen continues to show the build commit. Administrators also see the commit in **About DerridAI** and the account menu; non-admin users see the release version and codename without exposing the commit in those authenticated surfaces.
- The package metadata, API version constant, static HTML title, README family, package lock, build-time Vite/Storybook/Vitest definitions, release-consistency tests, and legacy DOM baselines are updated together.
- **How to test:** build the frontend from a git checkout and verify the browser title contains `0.81.0 - Fall River` plus the short commit; verify the sign-in footer shows the codename and commit; sign in as an administrator and check Settings → About DerridAI and the account menu; sign in as a researcher and verify the codename is visible while the commit remains hidden there.

## Evidence, Record Review, and retrieval reliability

### #238 — Automatic evidence binding cascade and embedding-array fix

- **Changed:** fixed the NumPy/Chroma ambiguous-truth-value failure in source embeddings, and replaced the old lexical-only opt-in backfill with a bounded evidence cascade for evidence-required metadata fields: deterministic text match → semantic/cross-encoder relevance → MMR/similarity → optional closed-choice LLM. Cascade bindings remain advisory/backfilled and do not silently confirm values.
- **Why:** metadata enrichment could crash on valid embedding result shapes, and values requiring evidence could remain unbound even when support was available.
- **How to test:** enrich a corpus with evidence-required fields; verify supported values arrive with reviewable evidence candidates and remain unconfirmed until a human acts. Exercise the same flow with the optional LLM last stage disabled and enabled, and verify NumPy-backed Chroma results do not raise the former truth-value exception.

### #241 — Durable live metadata/evidence refresh and canonical source-unit binding

- **Changed:** publishes `corpus.record_completed` only after the enriched Record is durably saved, refreshes the open Record and queue row in place, protects local drafts, and resolves automatic evidence against current source-unit topology before falling back to legacy blocks.
- **Why:** the review UI could show stale metadata/evidence or bind against obsolete source structure after enrichment.
- **How to test:** keep a Record open while enrichment completes and verify metadata/evidence appear without a hard refresh; edit a local draft during the event and verify it is not overwritten.

### #242 — Same-revision cache/race hardening for live review

- **Changed:** invalidates the bounded Record cache on explicit review resets, allows same-revision metadata/evidence hydration, and prevents a late realtime event from reactivating a Record after the reviewer has selected another one.
- **Why:** metadata changes do not always advance RecordRevision, so valid fresh state could be hidden by the cache; late events could also cause selection races.
- **How to test:** reset/re-enrich a Record without changing its revision and verify the open view updates; quickly navigate to another Record while completion events arrive and verify selection stays on the Record you chose.

### #243 — Non-blocking metadata confirmation

- **Changed:** restored optimistic metadata decisions so fields leave **Saving…** immediately, neighboring fields stay interactive, focus can advance, and failure reconciliation only clears the matching optimistic feedback.
- **Why:** a regression had made review wait on server persistence and could leave fields indefinitely locked.
- **How to test:** confirm a value, confirm no value, and batch-accept suggestions; each should release immediately. Force a save failure and verify authoritative state is refreshed without clobbering a newer queued decision.

### #244 — Bounded Ollama embedding batches

- **Changed:** sends Ollama `/api/embed` requests in configurable batches (default 256) and surfaces the provider's error body for non-2xx responses.
- **Why:** very large sources could exhaust loopback resources and fail with HTTP 400 when thousands of inputs were sent at once.
- **How to test:** ingest/index a source with thousands of source units under Ollama embeddings and verify indexing completes without one giant embed request; lower the batch size and confirm multiple bounded requests are used.

### #245 — Stable precedent panels and wrapping list metadata editors

- **Changed:** precedent components now key state on stable build/record/field identities instead of replacement record objects; empty kept precedents stay hidden until explicitly searched; free-value list fields use a wrapping/growing combobox editor instead of a clipped one-line input.
- **Why:** polling caused precedent panels to flicker/refetch and list metadata was hard to review.
- **How to test:** open a precedent panel during build polling and verify it stays open without refetch flicker; edit a multi-value field with long entries and verify values wrap and remain readable.

### #246 — Corpus Builder workspaces, live monitor, and model activity observability

- **Changed:** makes **Setup**, **Build**, and **Review** explicit workspaces; adds a live build monitor for stage/sub-operation/boundary/metadata/pipeline progress; exposes Document Intelligence provenance; makes extraction-quality second opinion media-aware; and adds administrator-only inspected prompt/schema/result/live-output views without putting prompt/source/model text on the WebSocket plane.
- **Why:** long builds lacked clear state, model work was difficult to diagnose, and PDF-specific review language leaked into other media.
- **How to test:** start a build and move between Setup/Build/Review; confirm the monitor updates live, Document Intelligence shows requested/actual provider and fallback, non-PDF media do not show PDF-only controls, and an admin can inspect model activity while ordinary realtime events remain text-free.

### #247 — Other-record evidence from the Evidence tab

- **Changed:** the Evidence tab can now add/remove source spans from other Records and preserves existing `external_block_ids` when local evidence is edited.
- **Why:** cross-record evidence previously required a metadata-editor path, and editing own-record evidence could silently delete already-bound external spans.
- **How to test:** bind evidence from another Record, then change an own-record checkbox; verify the external span remains. Reopen **Cite other records…**, clear the selection, and verify only the external spans are removed.

### #249 — Exclude provenance-incomplete RAG candidates instead of failing the entire run

- **Changed:** partitions retrieved Records by evidence sufficiency before evidence tags are assigned; incomplete Records are excluded and reported in warnings/stage diagnostics. The run still fails if every candidate is insufficient.
- **Why:** one incomplete retrieved Record previously aborted an otherwise supportable Research run.
- **How to test:** run Research against a mix of complete/incomplete Records and confirm an answer can proceed using only complete evidence with an exclusion warning; test an all-incomplete result set and confirm the run fails with per-record detail.

### #250 — Metadata schema editor focus stability

- **Changed:** unsaved field rows no longer use editable name/label text as Vue keys; they fall back to stable row identity.
- **Why:** typing the first characters of a new field remounted the row and dropped keyboard focus.
- **How to test:** add a new schema field and type its name continuously; focus must stay in the same input.

### #252 — Ingestion timeouts, accept-time evidence, enum preselection, and spaCy-first language packs

- **Changed:** moves expensive source extraction/OCR/page detection off the event loop, gives upload/URL imports a 15-minute client timeout, runs a non-LLM evidence cascade when accepting an unbound value, fixes enum suggestion preselection, makes spaCy the language-neutral Document Intelligence baseline, and adds admin-installed digest-verified language/model packs with atomic activation.
- **Why:** large ingestion could freeze the API or time out; metadata review had evidence and enum UX gaps; BookNLP is English-only and runtime model downloads conflict with controlled/local execution.
- **How to test:** load a large supported source and confirm the API remains responsive; accept an unbound suggested value and verify advisory evidence appears; verify model enum suggestions preselect; install a language pack from Settings → System and confirm a failed/cancelled install leaves the prior pack intact.

### #274 — Publication JSONL metadata, validation-fix routing, readiness UX, and System Data naming

- **Changed:** preserves assertion-backed scholarly root fields in exported corpus JSONL, makes **Fix** navigation reset the review workspace so the target field is visible, restores success-state CSS tokens, groups publication blockers by Record with progress, and renames the old Response Cache navigation label to **System Data**.
- **Why:** exported metadata could be silently stripped, blocker navigation could land on an invisible editor, and readiness status styling/copy was inconsistent.
- **How to test:** publish/export a Record with FieldAssertion-backed author/work/title and inspect JSONL; trigger a blocker and use **Fix** from any prior review mode; verify grouped issue progress and success indicators.

### #279 — Non-bypassable evidence support and provenance gates

- **Changed:** activates `evidence.reviewer.current@2`, requires deterministic direct-support validation plus a provenance gate for every selected reviewer evidence candidate, and records rejection reasons without source text in telemetry.
- **Why:** relevance scores alone must not establish evidence authority or allow an unresolvable source binding.
- **How to test:** request evidence suggestions containing both relevant-but-unsupported and directly supported source units; only support/provenance-valid candidates should survive. Inspect the pipeline trace for rejection reasons and source-binding gate stages.

### #301 — Semantic-map interaction/read-only fix and evidence-span hydration

- **Changed:** makes the Record semantic map drag-pannable, prevents bounded semantic graph view reads from writing durable checkpoints/build state, and restores evidence hydration from block IDs, source-unit IDs, and source spans in Review and Focus View.
- **Why:** graph exploration should be read-only, and evidence could disappear when represented by newer locator forms.
- **How to test:** pan the Record semantic map and confirm node navigation/zoom still work; repeatedly read a bounded graph view and verify no build mutation; open evidence backed by each locator form and verify the cited text is hydrated.

### #302 — Full tooltip/helper-text accessibility audit

- **Changed:** standardizes accessible tooltips/disabled reasons/status/health guidance across the shell and major workspaces, removes dependence on native `title`, keeps consequential provenance/evidence/authority guidance persistently visible, clarifies “LLM assessed” versus “verified,” and preserves attribution distinctions such as speaker → position holder → stance → target/proposition.
- **Why:** dense enterprise controls need keyboard/touch-accessible definitions without hiding decision-critical consequences or misrepresenting model confidence.
- **How to test:** keyboard through tooltips, status chips, disabled actions, and icon-only controls; verify focus/Escape/touch-style toggling, forced-colors behavior, and that missing model confidence is described as unavailable rather than zero.

## Document Intelligence and semantic/relationship maps

### #240 — GraphQL Document Intelligence/SourceDocument read surface

- **Why:** large read surfaces needed the same typed/queryable read architecture without hiding mutations inside GraphQL.
- **How to test:** open Sources and retained Document Intelligence views and verify they load through GraphQL; rerun analysis via REST and confirm the updated retained result appears. Verify non-admin SourceDocument access remains denied.

### #248 — Bounded semantic content graph for large corpora

- **Why:** the earlier graph rebuilt and returned an entire potentially quadratic co-occurrence network, timing out on large corpora.
- **How to test:** use a corpus with many entities, switch overview/focus/filter/density modes, page the index, and verify the UI reports truncation instead of freezing; navigate by keyboard and confirm reduced-motion/forced-colors behavior.

### #251 — Per-Record semantic maps and cross-Record graph walking

### #254 — Semantic map spacing/marker readability

- **Why:** dense maps were visually crowded.
- **How to test:** compare a dense Record map at wide and narrow widths; relations should be easier to follow and labels should remain readable.

### #258 — Better semantic-map readability plus Records/Works access

### #307 — Shared relation-workspace interaction model

## Metadata schemas, source intake, and corpus semantics

### #256 — Metadata schema format 2: field scope and document-field policy

- **Changed:** replaces `applies_to_work` with explicit `record|corpus` field scope, adds DerridAI-owned document-field policies with stable IDs and `required_for: evidence|publication`, migrates format-1 schemas in memory, and adds a **Document fields** schema-editor tab.
- **Why:** shared bibliographic facts should be supplied/inherited at corpus scope rather than rediscovered independently on every Record.
- **How to test:** open an old schema and verify it migrates without data loss; configure corpus-scoped/document fields and publication requirements; build and verify inherited assertions retain reviewer/detection provenance.

### #257 — NLP hints in the default metadata schema

- **Changed:** adds curated POS/NER candidate tags to configurable fields in the built-in scholarly schema and bumps that built-in schema to 1.1.0.
- **Why:** deterministic NLP candidate generation should be useful out of the box while remaining advisory.
- **How to test:** inspect the default schema's field hints and run enrichment; verify hints generate candidates but do not themselves populate/confirm values or establish evidence.

### #259 — Ask only for required document metadata that detection missed

- **Changed:** after source-load detection completes, Setup shows inputs only for schema-required document fields still missing; reviewer-supplied values override later manifest inference and are marked as reviewer supplied.
- **Why:** asking for title/author/etc. before detection duplicated work and obscured which values were found versus entered.
- **How to test:** load a source with complete embedded metadata and confirm no inputs appear; load one missing a required field and confirm only that field appears after detection, can be supplied, and persists as reviewer-authored inherited provenance.

### #268 — Corpus-neutral built-in LLM prompts

- **Changed:** removes hard-coded references to Derrida/named authors from prompts, threads runtime `document_author` context where available, prevents author from being collapsed into speaker/position-holder, adds author context to RAG grading/enrichment/segmentation, and versions changed prompt contracts.
- **Why:** DerridAI now supports general humanities corpora; prompts must not smuggle corpus-specific assumptions into attribution.
- **How to test:** build non-Derrida material and inspect admin prompt traces; no named-author fallback should appear, while actual document-author context should be present and separate from speaker/position-holder fields.

### #275 — Built-in Fiction and Non-fiction metadata profiles

- **Changed:** adds read-only, duplicable Fiction and Non-fiction schemas with stable field IDs, extraction guidance, evidence/assessment rules, controlled vocabularies, and POS/NER hints; preserves the historical default profile for compatibility.
- **Why:** different documentary genres need useful defaults without hard-coded runtime branches.
- **How to test:** create builds using each built-in profile, inspect fields/vocabularies and prompt generation, verify the built-ins cannot be edited directly but can be duplicated and customized.

## Pipeline Studio, versioned execution, and auditability

### #253 — Configurable Pipeline Studio architecture

- **Changed:** introduces typed pipeline definitions, server-owned strategy registry, immutable versions/assignments/traces, administrative APIs, backup integration, runtime instrumentation/retrieval primitives, and Pipeline Studio UI.
- **Why:** retrieval/LLM behavior was distributed across hard-coded chains, making it difficult to inspect, compare, version, or reproduce.
- **How to test:** open Pipeline Studio as an administrator, inspect built-ins and assignments, clone a version, change permitted settings, save/assign it, execute the corresponding feature, and verify a trace binds to the immutable definition/hash.

### #262 — Reviewer evidence suggestions execute through assigned pipelines

- **Changed:** adds an executable bounded reviewer-evidence adapter with explicit lexical/semantic/cross-encoder/support signals, candidate retention decisions, safe traces, and assignable current/conservative chains.
- **Why:** evidence suggestion behavior needed to be versioned without conflating relevance with evidentiary support.
- **How to test:** assign a supported reviewer-evidence pipeline, request suggestions, inspect candidate/stage telemetry, and confirm no source text or proposed values are copied into operational traces.

### #267 (landing #263) — Pipeline runtime integrity hardening

- **Changed:** makes Research stage configuration/fallback routing authoritative, binds trace stages to resolved immutable definitions, validates strategy config/collisions strictly, restores backups atomically, allocates clone versions on the server, and improves plain-language guidance/tooltips.
- **Why:** a configurable graph is only reproducible if the resolved definition, trace IDs, version allocation, and restore behavior cannot drift.
- **How to test:** clone/assign/run a pipeline and verify the trace stage IDs match the saved version; attempt invalid strategy settings/collisions and verify rejection; test backup restore failure and confirm the previous store remains intact.

### #273 — Metadata precedent retrieval becomes pipeline-executable

- **Changed:** compiles the metadata precedent chain (retrieve → scope → hybrid → optional CrossEncoder → quotas → MMR → pack) from an assigned immutable pipeline, while keeping schema eligibility, similarity floors, quotas, and authority rules outside the tunable graph.
- **Why:** precedent selection should be configurable/reproducible without allowing pipeline settings to redefine scholarly authority.
- **How to test:** clone a metadata-precedent pipeline, change candidate depth/MMR/packet budget, assign it, enrich a Record, and inspect telemetry for pipeline ID/version/hash; make resolution unavailable and verify deterministic fallback.

### #277 — Claim and response memory become pipeline-executable

- **Changed:** adds a shared bounded compiler for claim/response memory, makes retrieval depths/similarity/top-K pipeline-controlled, registers lexical degradation explicitly, and keeps grade/validation/support/owner authority gates mandatory.
- **Why:** memory retrieval mechanics needed reproducible tuning without making ungraded responses or unsupported claims eligible.
- **How to test:** assign custom claim/response memory pipelines, run Research with eligible memory, and inspect exact pipeline/hash/stage observations; deliberately remove a fallback and verify the configured failure behavior.

### #278 — Metadata pipeline traces at the point of review

- **Changed:** persists metadata-precedent traces in the shared trace store and on the reviewed Record, exposes exact pipeline/run identity in Corpus Builder Metadata, and makes lexical fallback an explicit stage/cause.
- **Why:** reviewers need to know which retrieval stages/fallbacks produced the precedents they are evaluating.
- **How to test:** enrich with semantic retrieval available and unavailable; inspect the Metadata panel trace and System Data execution record and verify normal/fallback stages and exact pipeline hashes agree.

### #280 — Operational health metrics

- **Changed:** aggregates recent immutable traces into feature/strategy counts, status, fallback/failure/warning incidence, average/p95 latency, provider/model calls, and candidate flow, exposed in Pipeline Studio **Operational health**.
- **Why:** operators need to distinguish whether a pipeline is functioning from whether its scholarly output is valid.
- **How to test:** execute several pipelines including a forced fallback/timeout, open Operational health, and verify counts/latencies/fallbacks update; confirm the UI labels the metrics as operational rather than quality/authority scores.

### #281 — Non-persistent Research A/B comparison

- **Changed:** adds an admin comparison endpoint/UI that runs two saved Research retrieval pipelines through real retrieval/reranking/diversity/provenance/context packing but stops before generation; retains bounded rank/overlap/latency diagnostics without source text and declares no winner.
- **Why:** pipeline changes need controlled inspection without creating Research answers, memories, grades, mutations, or ordinary traces.
- **How to test:** select two Research pipeline versions, run the same question, compare pool/rerank/evidence overlap and rank changes, then verify no Research job/answer/memory/ordinary trace was persisted.

### #286 — Fixed-case Research pipeline benchmarks

- **Changed:** adds immutable versioned benchmark cases, source/index fingerprints with drift detection, dedicated benchmark result storage/backup, exact pipeline snapshots/hashes, bounded reproducibility diagnostics, and a Pipeline Studio benchmark panel.
- **Why:** A/B runs become meaningfully repeatable only when the question, controls, source collection, and retrieval-relevant corpus/index identity are frozen.
- **How to test:** create a benchmark case, run two pipeline versions, confirm a saved result with hashes/fingerprint; mutate/rebuild the source index and verify the old case is rejected with corpus/index drift rather than silently rerun.

### #289 — Pipeline diagrams and full execution history

- **Changed:** separates **Pipelines**, **Executions**, and **Operations** workspaces; visualizes definitions and reached/unreached trace stages; adds search/filter/paging across all executions and deletion/clear-history actions that do not alter definitions or assignments.
- **Why:** configuration, run history, and operational tools had become too dense in one screen.
- **How to test:** inspect a definition diagram, run it, locate the execution by filters, open its execution diagram, jump back to configuration, delete the trace/clear history, and verify definitions/assignments remain.

### #292 — Automatic evidence recovery through versioned cascades

- **Changed:** removes production orchestration from the old direct cascade and routes enrichment/accept-time evidence recovery through the `evidence_recovery` assignment. Adds legacy-parity `evidence.recovery.cascade@1` and conservative cELF-oriented `evidence.recovery.celf@1`, explicit fallback-edge semantics, compliance stamping, and source-document identity guards.
- **Why:** automatic evidence recovery must be inspectable/versioned and must state whether a configurable chain preserves the required support/provenance structure.
- **How to test:** run both built-ins on the same supported field, inspect the trace and evidence pipeline stamp, force empty/unavailable/error paths, and verify only reached fallback stages execute. Remove source-document identity and confirm retrieval/model calls do not start.

### #293 / #303 A2 — Vector Store search through versioned pipelines

- **Changed:** #293's stacked slice, landed on master through #303, routes general Vector Store search modes through versioned `store_search.<mode>@1` pipelines.
- **Why:** direct store search was another hard-coded retrieval path outside Pipeline Studio audit/version control.
- **How to test:** assign a Vector Store search pipeline, run each supported search mode from the store workspace, and verify result behavior plus a trace bound to the assigned immutable version.

### #294 / #303 A3 — Metadata pre-fill retrieval through a versioned pipeline

- **Changed:** #294, landed through #303, moves metadata pre-fill retrieval/hints onto `metadata.prefill.current@1`.
- **Why:** pre-fill candidate acquisition should use the same versioned/auditable execution model as other metadata retrieval.
- **How to test:** run metadata enrichment with reviewed-memory pre-fill, inspect the selected candidates/hints and pipeline trace, then change a permitted retrieval setting in a clone and verify the new version is recorded.

### #297 / #303 A4 — Precedent evidence remapping through a versioned pipeline

- **Changed:** #297, landed through #303, routes ranking/remapping of precedent evidence candidates through `precedent.remap.current@1`.
- **Why:** adopting a precedent still needs evidence located in the current Record; that ranking step must be reproducible rather than implicit.
- **How to test:** open a Record with a reviewed precedent, adopt/use the precedent, inspect suggested current-record evidence, and verify the remap pipeline identity/trace.

### #299 — Pipeline diagram UX

- **Changed:** renames/refines the pipeline diagram, adds horizontal/vertical layouts, draggable stages with live edge routing, rich accessible stage infoboxes, clearer fallback-state visuals, and clearer glossary/compliance messaging.
- **Why:** the initial graph was useful but too static and jargon-heavy for routine inspection.
- **How to test:** switch layouts, drag stages, open stage details by keyboard/pointer, inspect fallback styling and cELF-compliance explanations in English and French.

### #303 — Land stacked Pipeline Studio slices A2–A4 on master

- **Changed:** carries the already-reviewed #293, #294, and #297 commits onto `master` without changing their behavior.
- **Why:** those PRs had merged into stacked feature branches after their base was already merged, so their deltas had not reached the default branch.
- **How to test:** use the three feature tests above; no separate product UI is introduced by the carrier PR.

### #304 — Corpus metadata-enrichment model calls through a versioned pipeline

- **Changed:** adds `corpus_metadata_enrichment` / `corpus.metadata_enrichment.current@1`; the default preserves primary provider ×2 attempts then review provider ×2 on error/timeout. One trace is retained per Record and per-group ledgers record pipeline/stages/provider/model/failure code but not prompts/answers.
- **Why:** the model-call chain itself was still hard-coded even after retrieval became pipeline-aware.
- **How to test:** run enrichment under normal success, retry→escalation, both-provider failure, and timeout; compare calls/outputs with legacy expectations and inspect per-Record trace identity in the execution ledger.

### #306 — Corpus segmentation boundary questions through Pipeline Studio

- **Changed:** adds `corpus_segmentation` / `corpus.segmentation.current@1` for the batch boundary classifier and second reader, sharing structured-stage runtime with metadata enrichment. Deterministic routing/budgets/block checks/confidence/text conservation stay domain-owned; unresolvable pipelines keep ambiguous boundaries rather than guessing.
- **Why:** segmentation's model decisions need the same versioned provider/attempt policy without making pipeline config responsible for conservation rules.
- **How to test:** run segmentation with primary success, escalation, failure, and an unresolvable assignment; inspect boundary decision pipeline identities and verify low-confidence/failure still keeps the boundary.

### #312 — Manifest, text touch-up, and reviewer evidence-choice model calls through Pipeline Studio

- **Changed:** adds `corpus.document_manifest.current@1`, `corpus.text_touchup.current@1`, and `corpus.reviewer_evidence_choice.current@1`, each preserving the existing primary×2→review×2 chain. Manifest pipeline identity stays in a separate checkpoint; touch-up/evidence proposals carry pipeline identity.
- **Why:** these were three remaining Corpus Builder model-call paths outside versioned execution.
- **How to test:** start/reanalyse a document manifest, request text touch-up, and use Evidence → **Ask the model**; inspect traces. Break assignment resolution and verify manifest falls back to embedded metadata with a warning while interactive touch-up/evidence requests fail explicitly.

### #314 — Evidence-recovery closed-choice provider/attempt settings

- **Changed:** makes `llm.closed_choice_evidence` honor stage `provider_role` (chain/primary/review) and `attempts` (1–4); distinguishes unavailable/timed_out/failed, marks true escalation, records actual provider/model/settings, and rejects these settings on reviewer-suggestion graphs where they do not apply.
- **Why:** a Pipeline Studio stage must actually control the execution parameters it displays.
- **How to test:** clone an evidence-recovery pipeline for review-first or split primary→review fallback, run it, and inspect calls/trace escalation. Select an unconfigured role and verify no model call occurs and the stage reports unavailable.

### #305 and direct commit 87678aa8 — Current pipeline/retention agent guidance and workflow semantics

- **Changed:** updates `AGENTS.md` to treat pipelines as a major backend boundary, document immutable identity/trace and retention/pinning rules, and adds implementation instructions for Pipeline Studio workflow semantics.
- **Why:** future changes need to preserve the architectural invariants established by this release rather than reintroduce direct model/retrieval orchestration or unsafe retention.
- **How to test:** documentation-only; review against the implemented pipeline/retention contracts and keep documentation contract tests green.

## Application shell, Research UX, Help, accessibility, and operations

### #255 — Seamless realtime Corpus Builder updates

- **Changed:** applies bounded build counters/progress directly from existing WebSocket events, surgically refreshes completed Records, reconciles REST fallback into existing reactive objects, and throttles admin-only live model-output REST snapshots.
- **Why:** replacing whole build/workspace objects during polling/realtime caused selection, scroll, and component state to jump.
- **How to test:** run enrichment while scrolling/selecting/reviewing; stage/count/Record updates should appear in place with no workspace remount. Disconnect/reconnect realtime and verify REST reconciliation preserves state.

### #264 — Dock background operations by default

- **Changed:** new/unspecified operation preferences default to top-bar docked mode; single-click expands, double-click undocks without firing the single-click action, drag is disabled while docked, and docked accessibility/forced-colors behavior is improved.
- **Why:** floating operation chrome obscured workspace content and had ambiguous state transitions.
