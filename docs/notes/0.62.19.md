# 0.62.19 — Configurable Chameleon

**Metadata schemas.** You can now define which metadata fields exist on JSONL records, what each may hold, and what the model is told to look for in each, then save the schema, share it as a file, and choose one per corpus build.

- **A schema** is groups (each group is one model call per record, with its own opening instructions, notes, closing remarks and evidence/confidence instructions) and a flat list of fields (name, label, type, group, the instruction the model receives, and for a choice field its allowed values with optional definitions). A field can require cited evidence, a stated confidence, or a person's decision before a record is accepted.
- **Locked core.** `region_type`, `primary_text` and `discourse_role` are in every schema and cannot be changed or removed: DerridAI's page-range and layout logic depends on them. Names DerridAI itself uses cannot be field names.
- **One schema per build, fixed.** A build copies its schema when it starts. Editing or deleting a saved schema afterwards changes nothing about it, and a build is never re-run against another schema.
- **The built-in schema** describes the fields and instructions DerridAI has always used. A test builds each prompt from it and compares against the prompts DerridAI used before (quotation and indexing are identical; in the discourse prompt the `stance` and `proposition_status` lines swap places).
- **Editor** in the Corpus Builder ("Manage schemas…", step 5 of setup): saved schemas, groups, fields, duplicate, delete, export, import, and "Try it on a passage", which shows a group's prompt or runs it on a passage with a model.
- **Export and import** use one JSON file with a format version and a checksum; import goes through the same validation as the editor.
- **The pipeline follows the schema:** prompts and the model's answer shape, which fields the model or a person may set, evidence, review, editing and its validation, the review panel and bulk edit, and the enrichment dialog's groups.
- No migration or compatibility code: a build made before this release has no schema copy and uses the built-in one.

## What is not done

- The metrics and ledger do not yet record which schema a build used (the build stores `schema_hash`).
- Groups other than `quotation` and `indexing` run on every record; there is no per-group routing rule in the editor.
- Checked in the browser against the mock API in light and dark mode; not on a real build, and the model preview was not run against a live model.
